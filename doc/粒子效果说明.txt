飞行雪绒粒子效果说明（LTS1.0.6pre6）

一、总体说明
- 事件入口：`EventType.PARTICLE_REQUEST`
- 渲染层：`lib/core/qt_bridge/particle_system.py`（旧 `qt_particle_system.py` 仅为兼容导出）
- 粒子脚本发现：`lib/script/practical/manager.py`
- 自动扫描目录：`lib/script/practical/*_particle.py`
- 更新机制：`tick` 推进真实状态，`frame` 仅负责插值绘制
- 运行语义：practical 粒子已统一切到 `tick/秒` 语义，不再依赖运行时 `frame_fps`

当前已注册粒子：20 个

三、统一事件格式
```python
Event(EventType.PARTICLE_REQUEST, {
    "particle_id": "scatter_fall",
    "area_type": "point",
    "area_data": (x, y),
})
```

区域数据格式
- `point`: `(x, y)`
- `rect`: `(x1, y1, x2, y2)`
- `circle`: `(x, y, radius)`

四、覆盖层与绘制性能
- 粒子实例的 `color`、`font` 使用 `lib.core.graphics.types.Color`、`FontSpec`；脚本不得保存 `QColor`、`QFont`、`QPixmap`、`QPainter` 等 Qt 对象，也不得实现接收 painter 的自定义绘制方法。Qt 后端创建并缓存字体，计算文字宽高和基线；新增视觉形状通过纯数据属性表达，由 Qt 或未来其他后端负责绘制。
- 粒子覆盖层在一轮粒子开始前固定到虚拟桌面几何；粒子存活期间不再根据联合包围盒移动或缩放顶层透明窗口，因此最外侧粒子变化不会带动整层抽动。
- 渲染空间使用 128px 二维固定矩形分块。tick、生成和异步回填时增量同步粒子保守绘制包围盒与分块归属，刷新旧块与新块的并集；FRAME 只复用缓存索引和当前占用块，不重新计算包围盒。连续脏块按行合并，保证旧像素被清除，同时避免整屏重绘。
- `paintEvent()` 只查询 Qt 脏区域命中的分块，并对横跨多个块的粒子去重；文本、线段、圆形和图片粒子都通过统一包围盒参与索引与精确裁剪。
- 粒子的绘制顺序和包围盒均由索引缓存；粒子移动、生成、死亡或排序字段变化时才更新对应索引状态。大块粒子不属于本系统的优化边界，由特效系统负责。
- 每次 tick 的插值起点取更新前的逻辑 `x/y`，不得从尚未走完的 `_render_x/y` 继续插值，否则会反复回拉运动轨迹并造成快慢速粒子抖动。
- 启用大批量异步更新时，后台线程只更新粒子快照；主线程继续绘制原对象，并在结果回填时保留快照提交后新生成的粒子。
- 粒子数量较少或无存活粒子时应尽早跳过屏幕查询、计算提交和无效重绘；效果脚本继续使用 `tick` 更新、`frame` 插值。

五、维护约定
- 新增粒子后，必须同步更新本文档
- 需要说明触发场景时，优先写“业务用途”而不是只写视觉形态
- 若粒子公开协议发生变化，请检查 `doc/README.md` 是否需要更新入口说明
- 若修改粒子时序，优先保持 `tick` 更新、`frame` 插值，不再回退到逐帧逻辑
