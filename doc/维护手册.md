# 飞行雪绒维护手册

更新时间：2026-09-01

本手册面向维护者和代码代理，说明当前工程边界、常见变更路径和验收方式。开始工作前先读 `doc/AI协作规范.md`，再按任务阅读专项文档。

## 1. 事实源与优先级

发生冲突时按以下顺序判断：

1. 可执行源码与测试。
2. 本手册和 `doc/README.md`。
3. 事件、游戏包等专项协议文档。
4. 根目录 README、贡献和发布说明。
5. 历史计划、整改清单和更新日志。

## 2. 启动与退出

### 启动链路

```text
启动程序.bat / 调试模式.bat
  -> lib/core/qt_desktop_pet.py
  -> lib/script/main.py::main
  -> ApplicationState
  -> APP_PRE_START / APP_INIT_READY / APP_START / APP_MAIN
```

`ApplicationState` 负责单实例、桌面应用、主窗口、管理器、托盘和最终清理。字体、公告、预加载、CMD、提示面板、登录窗口初始化和退出动画等 toolkit UI 生命周期统一由后端提供的 `ApplicationUiHost` 承接；长生命周期组件不得绕过主编排器自行结束应用。

Windows 用户目录和安装目录可能包含空格、`&`、`!`、`%`、单引号等字符。快捷方式同步通过编码后的 PowerShell 脚本和进程环境传递路径；`启动程序.bat`、`调试模式.bat`、`安装依赖.bat` 禁止启用 delayed expansion，普通与调试入口统一由 `lib/script/app/windows_launcher.ps1` 读取 `py.ini` 并使用 `ProcessStartInfo` 启动 Python。更新重启不得把批处理路径直接拼入 `cmd /c`。

开机启动设置由 `lib/script/app/autostart.py` 管理，使用当前用户的 Startup 文件夹创建并校验 `飞行雪绒.lnk`，不要求管理员权限；启用时会清理旧的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 项，启动时可将指向当前启动脚本的旧项迁移到快捷方式。托盘与设置面板只读取该服务的实际快捷方式目标，不以注册表值存在作为成功依据。

主界面就绪后，`AnnouncementController` 从固定 Gitee `RESC` 发布槽异步下载桌宠公告。公告文件使用按出现顺序解析的 `title`、`subtitle`、`text` 引号块，可重复出现多个 `subtitle` 和 `text`；正文窗口保持紧凑并独立滚动。公告的亮/暗配色跟随 `UI.workbench_light_theme`，并在 `CONFIG_UPDATED` 后热刷新。用户可仅抑制当日自动显示或永久抑制自动显示，状态写入 `<用户根>/user/state/announcement.json`，最近一次成功内容缓存到 `<用户根>/cache/announcement.txt`。“界面与动画”页的“不显示公告”复选框读取并修改同一份永久抑制状态，取消勾选不会清除当日抑制。托盘“桌宠公告”入口不受自动显示偏好限制；每次手动打开都先进入加载态并发起独立的无缓存请求，只接受最后一次请求的结果，网络失败时才回退到本地缓存。

启动/退出动画的 `ANIMATION.start_animation_duration` 与 `ANIMATION.exit_animation_duration` 使用 0.5x~2.0x 的倍速值，默认 0.5x；播放器在加速时均匀抽帧，减速时放宽帧间隔，滑块旁显示“当前倍率/实际时长”（如 `0.5x/1.5s`），实际时长依据当前帧数和 `frame_fps` 计算。启动描述推荐 3.0s，退出描述推荐默认速度。

### 退出链路

正常退出由 `ApplicationState.request_exit()` 发起，依次停止主窗口、清理运行时服务、清理视觉组件并退出桌面后端事件循环。`ApplicationState` 只依赖 `lib/core/application_runtime.py` 的 `ApplicationRuntime` 协议；当前 `QApplication/QEvent/QTimer` 实现位于 `lib/core/qt_bridge/application_runtime.py`。`APP_EXIT` 广播退出阶段，`APP_QUIT` 请求主编排器开始退出。

最后一个退出阶段使用带退出码的 `QApplication.exit()`，处理 `DeferredDelete` 后等待 `aboutToQuit` 确认；未确认时会关闭残留顶层窗口并再次请求正常退出。事件循环返回后还要短暂等待非守护线程结束。15 秒进程级 watchdog 只作为整个退出链路卡死时的最终兜底，正常收尾确认后必须取消。

事件循环返回后，`ApplicationState` 还会调用当前 `DesktopBackendBundle.cleanup` 执行后端级幂等兜底，再清理事件中心。该边界负责释放未被业务对象显式回收的 scheduler、event pump、世界对象和 native host；应用状态构造失败时同样必须调用 bundle cleanup 并释放单实例锁。

需要重启时向 `APP_QUIT` 传入 `restart: true`。主编排器必须先成功拉起脱离当前进程树的重启 helper，再走完整退出流程并释放单实例锁；helper 等待旧 PID 真正退出后启动新实例。helper 创建失败时不得退出当前实例。重启 helper 不属于本地托管服务，服务清理不得结束它；界面组件也不得自行拉起副本。启动阶段诊断写入 `logs/restart.log`。

分发包更新只接受固定 GitHub/Gitee 发布槽中的离线安装器 EXE。主进程下载并流式校验
PE 尾记录、SHA-256 和 ZIP 目录；用户点击“启动安装器并退出”后通过 `APP_QUIT`
优雅退出。原生安装器接管目录切换，使用包内 Python/Node，完成后写回更新状态；主进程
不覆盖文件、不执行外部 Python/Node，也不把源码 ZIP 当作更新包。

维护约束：

- 新增长生命周期对象必须提供幂等 `cleanup()`。
- 事件订阅必须有对称 `unsubscribe()`。
- 网络流设置有限连接/读取超时，并在 cleanup 时关闭活动响应。
- 子进程保存句柄；先正常终止，超时后结束进程树。
- 后台任务统一使用 `lib/core/compute_hub.py`，不得新建无所有者线程池。
- 用户点击后必须立即开始的长耗时 I/O 使用 `ComputeHub.submit_interactive_io()` 的保留执行槽，不能排在登录、音乐下载等共享后台队列之后。
- 设置面板保存配置必须先完成 `ComputeHub.submit_interactive_io()` 写盘并确认成功，再执行关闭或重启；失败时保留面板，重复点击不得覆盖原保存任务的完成动作。
- `os._exit()` 只能作为最终超时兜底。

## 3. 模块边界

### 核心层 `lib/core`

核心层包含事件、绘制、层级、输入、物理、调度、日志和主宠窗口。业务模块可以依赖核心层，核心层不得反向依赖具体 provider 或工作台页面。

- 绘制排序与批次：`graphics/scene.py`、`graphics/commands.py`、`graphics/ordering.py`
- 视觉表现边界：`doc/视觉表现契约.md`；Qt 当前输出是迁移基准，bridge 只执行绘制
- 共享视觉转译：`graphics/visuals.py`、`graphics/application_visuals.py`
- 业务绘制入口：`draw_core.py`、`unified_draw.py`
- Qt 无关图形契约：`graphics/types.py`、`graphics/commands.py`、`graphics/scene.py`、`graphics/anchors.py`、`graphics/capture.py`
- 窗口层级与后端宿主协议：`layer_manager.py`、`window_host.py`
- 事件中心：`event/center.py`
- 调度核心与后端协议：`timing/manager.py`、`timing/scheduler.py`
- 应用事件循环协议：`application_runtime.py`
- 应用 UI 生命周期协议：`application_ui.py`
- 桌面后端选择路由：`backend_router.py`
- 桌面后端服务 bundle 与注册：`desktop_backend.py`
- 主宠窗口宿主回调与清理：`pet_host.py`
- 托盘与视觉覆盖层生命周期：`tray_host.py`、`overlay_host.py`

旧 `core/object`、`core/render` 包和 `topmost_manager.py` 已删除，不得恢复兼容壳。

- 音乐搜索门面：`music/`

## 4. 工作台

工作台采用两级懒加载：启动预加载器不创建工作台；打开总览只创建工作台壳；进入设置页或工具页时才调用页面工厂。

工作台是普通任务栏窗口，不注册 `LayerManager`、不使用 `WindowStaysOnTopHint`，也不提供置顶开关；只有用户主动打开时才正常激活窗口。工作台可见期间不修改桌宠全局 FRAME 频率，并使用 `resc/icon.ico` 作为窗口与任务栏图标。设置面板的装饰性 TICK 订阅只在独立面板真正可见时存在，嵌入工作台或隐藏后不得空转。

工作台顶栏搜索框左侧的粉青色明暗主题开关保存到 `UI.workbench_light_theme`，默认关闭为当前暗色主题；开启后使用白色/粉色表面和深灰蓝文字，并通过 `CONFIG_UPDATED` 热重载工作台样式。“界面与动画”设置页不再提供重复入口。

工作台及其动态创建的控件统一使用 `lib.core.qt_bridge.font.get_ui_font()` 创建 Qt 字体；`config.font_config` 只保存字号、字体路径和已注册字体族。控件树刷新时只替换字体族，不覆盖字号、粗细和自定义绘制字体。

相关位置：

- 窗口与宿主：`lib/script/ui/workbench_window.py`
- 页面注册：`lib/script/workbench/page_registry.py`
- 内置工具页注册：`lib/script/workbench/builtin_pages.py`
- Qt 工具页共享宿主：`lib/core/qt_bridge/workbench_page.py`
- 设置 schema：`lib/script/workbench/settings/schema.py`
- 设置布局：`lib/script/ui/workbench_settings_layout.py`
- AI 设置控制器：`lib/script/ui/ai_settings_panel.py`
- 办公任务页：`lib/script/ui/office_page.py`
- 办公权限窗口：`lib/script/ui/office_approval_controller.py`、`office_approval_dialog.py`

约束：

- 页面元数据使用 dataclass，不转回 legacy dict。
- 新工具页提供无参数 factory，首次访问时创建。
- 故障跟踪与游戏包等内置工具页的元数据和 factory 统一由 `builtin_tool_page_specs()` 提供，不得在托盘或工作台入口重复维护页面 ID、标题和构造逻辑。
- 同时支持独立窗口与工作台嵌入的 Qt 工具页继承 `QtWorkbenchToolPage`，通过 `refresh_workbench_page()` 刷新数据；工作台不得识别页面私有的 `refresh_games()`、`_refresh_now()` 等方法。嵌入页使用独立实例，不得把其它入口持有的独立窗口重新设置父对象后复用。
- 页面嵌入后不得保留独立窗口旗标或重复层级注册。
- 页面关闭时释放信号、定时器和后台任务。
- 不把新功能继续堆入 `ai_settings_panel.py`，新页面放入 `workbench/` 或专属模块。
- AI 回复模式是单一路由：福利 API、手动 API、本地 Ollama 和规则回复之间不做失败回退。模式专属配置只在对应模式下显示。回复模式区同时提供自动陪伴开关和 1~20 分钟的固定间隔滑块；保存值写入 AI 用户配置，运行时转换为毫秒定时，游戏模式启用时仍优先使用固定 5 分钟覆盖。
- AI 回复语音朗读的文本长度范围为 20~256 字，默认上限为 256；超长回复优先保留不超过上限的首句，否则按上限截断后送入 ONNX 语音。
- AI 工具调用优先使用 `lib/script/chat/native_tools.py` 定义的原生 Function Calling schema。OpenAI 兼容接口与 Ollama `/api/chat` 将结构化调用放入 `STREAM_FINAL.tool_call`，调度器不得再从显示文本反推参数；模型或网关拒绝 `tools` 字段时按目标缓存该能力并回退到既有 `###指令###` 文本协议。递归回忆、窥屏等设置 `allow_tool_commands=false` 的请求不得携带原生 tools。
- 福利 API 配置由 `lib/script/chat/welfare_api_config.py` 从 GitHub/Gitee 发布源并发测速获取密钥与地址。模型使用程序内置的固定标识，不依赖服务端实现 `/models`：默认模型为 `agnes-2.0-flash`，“智力提升”开启后使用 `agnes-2.5-flash`；配置下载超时固定 10 秒，首次失败后最多重试 3 次。
- 手动 API 的模型探测只辅助选择该路由的模型：设置面板以当前未保存的地址和密钥异步请求 OpenAI 兼容 `/models`，失败时保留用户当前输入。模型字段始终允许手工输入；无协议的公网地址按 HTTPS、本机地址按 HTTP 规范化后保存。
- 语音设置在 ONNX 包有效时显示；检测到旧 `start_gsvmove.bat`、缺失包或损坏包时，面板顶部显示“安装最新语音包”。有效包和损坏包同时提供带确认的后台删除入口，删除后立即刷新为可重新安装状态。安装窗口中的“后台安装”只隐藏界面、不取消任务；再次点击安装入口可恢复进度，后台仅在关键阶段以桌宠气泡提醒。面板开放当前 v2Pro 实际消费的采样温度、Top-K、Top-P、重复惩罚、语速、分句、片段停顿、随机种子和最大解码步数；批处理、流式及 v3/v4 专属兼容字段不显示为有效设置。安装与包管理 UI 位于独立的 `voice_package_installer.py`，不得继续堆入设置面板。

### 办公模式

普通文本先发布 `INPUT_TEXT`，由 `InteractionModeService` 单点路由到陪伴聊天或办公任务；`/`、`#` 协议保持不变。每次应用启动固定为陪伴模式，不持久化上次模式。模式 generation 是异步结果的有效性令牌：切入办公模式后，自动陪伴、流式气泡、语音和工具调度不得提交迟到的陪伴结果，自动语聊也要停止。

办公页支持新建/恢复历史任务、继续要求、取消、工作目录、运行状态、对话、推理文本、Todo 与工具事件。右键输入框路由到办公模式时，若没有活动任务，会按 `updated_at` 续接最近修改且具有办公后端会话的任务；工作台“新建任务”始终显式创建新任务。`#new` 是办公快捷命令，会切入办公模式并准备一个不带空消息的新对话，下一条普通输入才创建任务。任务历史提供带确认的删除入口；运行中的任务必须先取消，不能直接删除。默认工作目录由 Windows Known Folder API 解析为桌面下的 `飞行雪绒办公区`；用户可为新任务另选目录。任务和后端会话状态保存在 `<用户根>/user/state/office/`，同时只运行一个前台办公任务；应用退出时活动任务标记为取消，侧车先收 `shutdown`，超时后才结束自有进程树。

任务开始或新一轮推理时，OfficeService 通过普通 `INFORMATION` 将带 `kind=thinking` 的“思考中”加入桌宠气泡队列，避免打断当前尚未完成最短停留时间的气泡；任一后端的首个 `assistant/chunk` 文本分片通过 `UI_BUBBLE_REMOVE` 撤销该任务的思考气泡，再按办公状态刷新节奏静默替换为流式文本，不触发语音；稳定的 `assistant/message` 使用最终气泡停留时间并强制替换思考气泡，再发布一次 `AI_VOICE_REQUEST`。办公语音先排除 Markdown 围栏代码，再复用聊天回复的长度与中英语言策略；推理文本、Todo、思考气泡和工具事件不播报，语音模块关闭时仍由 `GsvmoveService` 按用户设置忽略请求。

`OfficeService` 只复用 `config.ollama_config.get_active_config()` 当前选中的福利 API 或手动 OpenAI 兼容路由；Ollama 与规则回复不进入办公后端。办公设置只提供 DSH 后端，DSH 实现 `fsv-office/1` JSONL 的启动、创建/恢复、继续、取消、审批和关闭协议，并由 `office/runtime.py` 按配置惰性创建。DSH 使用固定 Node 侧车。API key 只在任务启动时从工作台密钥存储读取，通过 JSONL `configure` 命令写入侧车内存，不写入 profile、环境变量、任务文件或日志。办公系统提示词的项目级唯一来源是 `resc/agent/office_system_prompt.txt`；DSH 运行时读取该资源。会话消息保存在 `<用户根>/user/state/office/dsh-sessions/`，不进入项目工作目录。DSH profile 使用 `dsh-llm-pi-ai` 的自定义 `openai-completions` 路由。未知网关均不得注入厂商专属 `thinking` 或 `reasoning_effort`。

DSH 沙箱默认为 `workspace-write`。越界操作发布权限请求，许可窗提供“允许”“始终允许”“拒绝”；“始终允许”只对当前任务有效。办公页与权限许可窗共同使用 `lib/script/ui/office_style.py` 的工作台明暗主题、粉青强调条、控件状态和操作层级，不各自维护一套颜色。Qt 主进程持有 `OfficeApprovalController`，DX 进程收到请求后复用隔离 Qt workbench helper 并直达 `office` 页。helper 使用版本 1 的原子请求文件、复用仍存活的进程；办公状态与命令使用独立版本 1 文件 IPC，不跨进程共享 QWidget 或业务单例。

## 5. 配置与用户数据

`config/config_*.py` 只存程序默认值，运行时禁止改写 Python 源文件。普通设置通过 `config.user_settings` 保存为版本化稀疏 JSON；密钥和登录态使用独立 secrets/state 路径。麦克风识别使用 `webrtcvad-wheels` 按 20ms PCM16 帧做语音端点检测；`microphone_denoise_enabled` 控制整句 NumPy 频谱软降噪，`microphone_denoise_strength` 控制软掩蔽强度，`microphone_noise_gate_threshold` 仅在缺少静音参考时参与噪声帧选择。手动语聊检测到说话后约 0.6 秒静音即结算，显式停止会立即结算；自动语聊保留起始预录和配置的句尾静音保持。整句收集完成后才创建 Vosk 识别器，降噪结果为空时使用原始 PCM 重试，最终只发布整句文本。

```text
默认值: config/config_*.py
用户覆盖: <用户根>/user/settings.json
状态: <用户根>/user/state/
密钥: <用户根>/user/secrets/
缓存: <用户根>/cache/
```

旧路径只允许一次性迁移读取。迁移必须有唯一 migration id、可重复执行、不覆盖新值，成功后只读写新位置，并提供迁移与幂等测试。

AI 密钥保存到 `<用户根>/user/secrets/ai.json`。设置面板每次打开都重新读取该文件，不能只使用模块首次导入时的内存值，以保证跨进程写入和重启后的配置一致。

人格词以仓库内 `resc/persona.txt` 作为默认模板。“设置人格词”首次打开时将当前有效模板初始化到 `<用户根>/user/persona.txt`，只在用户文件不存在时创建；运行时优先读取用户人格，再兼容旧自定义路径，最后回退默认模板。程序更新不得覆盖已存在的用户人格文件。

通用配置保存使用 `config.general_user_settings.save_general_values()`；不要在业务模块中自行解析或正则修改配置源码。

渲染后端选择保存于 `UI.render_backend`，稳定值为 `qt`、`directx`、`opengl`、`vulkan`，只在下次启动时应用。后端目录同时声明可启动性和成熟度：Qt 标记为当前可用，DirectX 标记为实验性功能，OpenGL/Vulkan 仍为尚未接入。实际启动时若对应配置器未注册、未实现或初始化失败，必须回退 Qt 并记录请求值、实际值和原因；实验性后端成功启动时记录兼容性警告。

## 6. 事件、调度与绘制

事件类型只能定义在 `EventType`。payload 使用字典，新增字段应允许旧订阅者忽略。后台线程发布事件时，由 `EventPump` 切回事件中心线程；Qt pump 仅是 `qt_bridge` 的一个实现。

已有后台组件应直接通过线程安全的 `EventCenter.publish()` 发布结果，不得为线程切换再创建私有 `QObject/pyqtSignal`；非 Qt 后端通过注入其他 `EventPump` 保持同一语义。

修改事件时同步 `事件系统使用说明.txt`、`已注册的事件.txt` 以及生产者和消费者测试。

帧、tick、GIF 帧和延迟任务由 `TimingManager` 负责。不要用散落的永久 `QTimer` 替代共享调度，除非计时器天然属于控件生命周期。

`TimingManager` 仅依赖 `timing.scheduler.Scheduler`，Qt 桌面宿主在组合边界注入 `qt_bridge.scheduler.QtScheduler`。新增非 UI 定时核心应复用该协议或共享调度，不得重新把 `QObject/QTimer` 引入 `timing/manager.py`；组件退出时调用 `TimingManager.cleanup()` 释放事件订阅和后端计时器。

DX 组合由 `dx_bridge.desktop_backend.DxDesktopBackend` 统一拥有一个 `DxLoopContext`，并向 `DxScheduler`、`DxEventPump`、`DxApplicationRuntime`、屏幕/截图、主宠、粒子/特效覆盖层、托盘、应用 UI 和世界对象工厂注入同一上下文。循环只允许 owner 线程执行回调和轮询 native host；worker 只通过 `post()`/`EventPump.emit()` 唤醒。周期任务迟到时不得补放调用风暴，停止或 cleanup 后不得再投递；窗口和托盘宿主必须显式注册并在关闭时注销。`DxScreenProvider` 查询时重新枚举显示器，`DxScreenCapture` 只返回 PNG bytes，`DxPetWindow` 关闭时先释放核心状态再注销 native host。`DxTrayHost` 使用 ABI v9 的通用托盘命令事件和菜单状态接口提供公告、控制面板、CMD、游戏模式、鼠标穿透、开机启动、清理、作者主页和退出入口；控制面板由 `ApplicationUiHost.open_settings()` 承接，DX 只启动隔离 Qt workbench helper，主进程不导入 Qt。文件与系统 I/O 由 `ApplicationState` 投递到 `ComputeHub.submit_interactive_io()`。DX 配置器已由启动入口惰性注册，并作为实验性后端开放尝试；DX 组合必须向音乐服务显式注入无 Qt 的播放器选择，不得导入或实例化 `QtMusicPlayer`/QtMultimedia。DX 自动公告已使用共享 core 服务和原生窗口；共享设备资源、真实硬件、DPI 和多屏验收仍属于稳定性闸门，初始化失败时继续回退 Qt。

聊天流式刷新、自动陪伴和 Ollama 周期探测同样使用独占 `Scheduler`，由 `ApplicationState` 注入 Qt 后端。业务模块不得自行导入 `QTimer` 或创建 `QtScheduler`；需要 single-shot 行为时，周期计时器回调必须先停止，再按需要重新排程。聊天截图依赖 `graphics.capture.ScreenCapture`，Qt 主屏幕抓取只允许位于 `qt_bridge.screen_capture`，模型侧只接收 PNG `bytes`。

跨后端绘制请求统一使用 `DrawCore`，桌面覆盖层和需要受管置顶的窗口统一使用 `LayerManager`，并在销毁时 unregister。工作台等普通任务栏窗口不注册全局层级，也不得使用 `WindowStaysOnTopHint`。`LayerManager` 只依赖 `window_host.LayerWindowHost` 的存活、可见、前置和原生堆叠能力，不得调用 QWidget 或 Win32 API；具体桌面后端通过 `LayerWindowHostFactory` 适配窗口。`QtRenderCore` 只用于明确的 Qt 控件内部 painter 回调，不是跨后端绘制入口。

视觉表现统一遵循 `doc/视觉表现契约.md`。当前 Qt 输出是颜色、排版、尺寸、透明度、动画和特效的迁移基准，但 Qt 类型和隐式默认值不是契约。主题 token、组件状态、布局、文字换行与基线、资源选择、采样、混合、动画和效果参数必须在后端无关层解析为不可变视觉描述；Qt、DX 及后续后端只负责资源转换、命令栅格化、合成和呈现。不得在 `qt_bridge` 或 `dx_bridge` 中新增产品色值、布局常量、业务类型分支或私有效果算法。

视觉收敛的目标坐标契约规定：桌面窗口位置和显示器几何使用物理像素，窗口内容、字号和 `DrawBatch` 使用 96 DPI 逻辑像素，由后端在绘制目标边界按 `dpi / 96` 只换算一次。DX 宿主、主宠锚点、应用 UI 和世界对象已按该分层实现，并由 100%/125%/150% DPI、负坐标和逻辑命中测试覆盖；真实硬件多屏热插拔与第三方输入法仍属于手工验收项。采样、alpha 合成、抗锯齿、线帽、文字基线、变换中心等会影响视觉的行为必须成为显式命令字段或共享布局结果，不能依赖 QPainter、Direct2D 或 DirectWrite 的默认值。

`lib/core/graphics/` 保存与后端无关的 `Point`、`Rect`、`Color`、`FontSpec`、`RasterFrame`、`ImageResource`、`DrawRequest`、`SpriteCommand`、`TextCommand`、`LineCommand`、`RectCommand`、`EllipseCommand`、裁剪/变换命令、`ResourceRevision` 和 `DrawBatch`。`RasterFrame` 固定为紧密排列的 RGBA8888 字节；`DrawScene` 只保存不可变资源、帧索引和请求状态，并为每次绘制生成已解析、按 `layer/z/order` 排序的不可变批次。批次同时携带当前资源 revision 快照，后端必须在资源消失或 revision 变化时淘汰缓存。业务状态和跨后端绘制请求不得新增 Qt 类型或 painter 回调。

GIF 由 `graphics/gif_loader.py` 解码为纯 `ImageResource`。`DrawBackend.render(batch, target, viewport)` 只消费不可变批次，`viewport` 使用核心 `Rect`；后端拥有 target 和资源转换缓存。Qt 的 `QImage/QPixmap/QPainter/QRect` 转换仅位于 `qt_bridge`。明确的 Qt 游戏控件仍可使用 `qt_bridge.render_core.QtRenderCore` 管理本地 painter 回调，但该类型不从 `graphics` 或 `unified_draw` 导出。

`backend_router.py` 保存稳定后端目录、配置器注册和启动选择结果；它不得导入 `qt_bridge`。`desktop_backend.py` 通过不可变 `DesktopBackendBundle` 原子注册绘制后端、应用运行时、应用 UI 宿主、调度器、截图、主宠窗口、粒子/特效覆盖层、`TrayHostFactory`、事件泵、一次性延迟、虚拟屏幕、按点屏幕、层级窗口宿主工厂和可选的后端级 cleanup；兼容 getter 只能从当前 bundle 读取，不能再增加彼此独立的服务全局变量。核心模块不得导入具体后端。具体后端注册由启动组合入口负责，`lib/script/main.py` 只读取已选 bundle；未配置桌面后端时，核心导入、被动窗口宿主与无窗口测试必须仍可运行。

退出编排只使用 `TrayHost` 的回调绑定、初始化、隐藏和 `cleanup()`，使用 `OverlayHost.flush_immediately()/cleanup()` 清理视觉覆盖层，并通过 `PetWindowHost.shutdown_host()` 关闭主宠宿主。Qt signal、`QWidget.close()/deleteLater()`、托盘单例释放和主宠 `TimingManager` 清理不得泄漏回 `ApplicationState`；具体行为由 `qt_bridge.tray_host`、Qt 覆盖层和 `QtPetWindow` 承担。

Qt 收敛按以下顺序推进：先抽出粗粒度 `ApplicationUiHost`，再把后端注册移出 `main.py` 并实现按选择惰性导入；随后补齐 `WindowHost v1` 的几何、显示、重绘、穿透、激活/IME 和输入能力；再扩展文字、形状与裁剪绘制命令；最后完成 DX/WARP 离屏原型。上述核心契约和 DX/WARP 命令映射均已完成；ABI v9 的 `DxWindowHost` 已分离物理按键、Unicode 文本和 IME 预编辑/提交事件并接通 `WM_POINTER*`，并用 `fsdx_measure_text` 暴露 DirectWrite 字形度量。`TrayHost` 已提供稳定 `TrayCommand`/`TrayMenuState` 契约，完整原生日常菜单由 DX 和 Qt 共用主协调路由。共享循环、调度、事件泵、屏幕、截图、退出链、主宠、托盘、粒子/特效、世界对象、原生命令/提示/二维码/公告/音响 UI 和完整 DX bundle 已组成阻断 PyQt 的 `ApplicationState` 启停组合。workbench helper 的进程复用、页面请求和办公 IPC 已落地。DirectX 现可从设置中选择并以实验性功能启动；游戏 helper、其它复杂 Qt 页面 IPC、共享设备资源和真实硬件/DPI/多屏/第三方输入法验收仍是稳定性闸门，失败时回退 Qt。

主宠窗口后端通过 `pet_host.PetHostCallbacks` 向业务层提交 `MouseInput`、`KeyboardInput`、`Point` 和渲染准备请求。当前 QWidget 原生事件、Qt 输入转换及兼容几何接口位于 `qt_bridge.pet_widget.QtPetWidget`；`PetWindow` 不得重新实现 `paintEvent`、鼠标/键盘原生事件或直接解析 Qt event。

主宠移动队列、插值、拖拽接管和 moving/idle 状态协作由无 Qt 的 `PetMovementRuntime` 统一管理；窗口宿主只通过位置、状态和方向回调承接副作用。移动参数使用纯 `MovementSettings`，由桌面组合边界从现有配置注入，不得让移动算法通过配置聚合模块间接加载 Qt。

实体位置迁移期间优先使用 `get_core_position()` 和 `get_core_geometry()` 获取 `Point/Rect`；`get_position()`、`get_geometry()` 只保留为 Qt UI 兼容接口。主宠与对象管理器的生产调用已迁移到核心接口，新增逻辑不得继续依赖旧接口。世界对象资源由 `graphics.image_loader` 解码为 `ImageResource`；对象管理器通过 `world_objects` 门面取得 `WorldObjectInstance`、核心 `Point/Rect`、状态和运动快照，不得直接调用后端图片、窗口或物理体的原生接口。`UI_ANCHOR_RESPONSE.anchor_point`、`ENTITY_POSITION_RESPONSE.position` 以及实体状态响应中的位置和移动目标统一使用 `graphics.types.Point`；Qt UI 消费者只可在接收边界转换为 `QPoint`。

桌面对象管理器位于 `lib/script/obj-*/manager.py`，只依赖 `graphics.image_loader`、`world_objects.py`、`screen_utils.py` 和核心 `Point/Rect`。资源和对象实例都必须使用后端无关契约；当前 Qt 的摩托、闹钟、沙发、雪堆、雪球、雪豹和音响窗口位于 `lib/script/ui/world_objects/`，由组合根注册给 Qt 后端，业务管理器不得直接导入这些类型或读取对象私有字段。

DX 的 `DxWorldObjectBackend` 已能创建同样七类对象并提供原生窗口、GIF 帧推进、核心几何、物理运动、拖拽、翻转、点击穿透和淡出。摩托连续加减速与二段跳、闹钟重复弹跳、雪豹定时转向等 Qt 行为已补齐；对象专属音效尚未等价。当前每个对象还拥有独立 DX runtime/device，大量对象场景完成共享资源改造前不得视为性能验收通过。

粒子覆盖层在一轮粒子开始前固定到虚拟桌面，存活期间禁止按联合包围盒移动或缩放顶层窗口。渲染使用 128px 二维固定矩形分块：tick、生成和异步回填时增量同步粒子包围盒与分块归属，刷新旧块和新块的并集；FRAME 只复用缓存索引和当前占用块，不重新计算包围盒。连续脏块按行合并后提交刷新，`paintEvent()` 直接查询脏区域命中的块并对跨块粒子去重，同时复用绘制顺序和包围盒缓存。tick 插值起点使用更新前的逻辑坐标；大批量异步更新使用隔离快照，禁止后台线程修改正在绘制的对象。无存活粒子时跳过屏幕查询和计算提交。

粒子脚本的 `color` 和 `font` 分别使用 `graphics.types.Color`、`FontSpec`，不得保存 `QColor/QFont` 或接收 `QPainter` 进行自定义绘制。粒子布局、文字宽高与基线、形状、bloom、羽化和 alpha 分配由共享视觉层确定并生成声明式命令；新增表现应扩展纯视觉数据或通用命令契约，不得增加 Qt/DX 私有渲染分支。

粒子、特效运行时、命令输入框外壳、命令框相对主宠的锚点布局及七类世界对象批次现由 `lib/core/graphics/visuals.py` 把纯业务状态转换为文字、线段、矩形、椭圆、sprite 命令或纯几何结果，并统一处理主宠目标尺寸、效果图片缩放与边缘羽化。世界对象共享逻辑包括 sprite/动画帧、透明度、翻转、中心缩放、摩托抖动、音响 EMA/指数缩放和闹钟倒计时排版；Qt 世界对象只执行共享批次。二维码主体、action button 的 normal/hover/pressed/disabled 状态、DX 基础通知面板和 Qt 聊天气泡现由 `lib/core/graphics/application_visuals.py` 生成后端无关视觉描述；气泡的换行、自适应尺寸、三层背景、混合字体分段位置及相对主宠的锚点/屏幕夹取均由 `BubbleVisualDescription` 和纯几何函数决定，Qt 只注入 `QFontMetrics` 的低级宽度/基线数据并通过 `QtDrawBackend` 执行批次。整个 `dx_bridge` 只选择 presenter、管理原生窗口/事件并提交批次，不得导入 PyQt，也不得实例化产品 `Color`、`FontSpec` 或具体绘制命令。

命令提示框的三层背景、自适应尺寸、默认/哈希行、选中态、分隔线、混合字体、页码和行命中矩形已由 `graphics.application_visuals.CommandHintVisualDescription` 统一；Qt `CommandHintBox` 只注入低级 `QFontMetrics` 并执行批次。DX `DxCommandHintWindow` 也执行同一描述，支持跟随命令框、筛选、键盘导航、补全、翻页和点击执行；真实 DX host 使用 ABI v9 DirectWrite 度量，无测量能力的测试宿主才使用 portable 回退。鼠标穿透、放大、缩小、关闭、启动鸣潮、聊天模式、交互模式和更多功能八个矩形附属按钮统一使用 `build_rect_action_button_visual()`；DX 已用单个原生窗口承载共享三行布局、批次和 hover/pressed 命中，“更多功能”固定在“启动鸣潮”正上方，全部动作经 `desktop_actions` 后端中立分发。二维码 action button 由共享 QR presenter 生成，Qt `QPushButton` 仅作为透明输入适配器，DX 使用同一 `action_rect` 完成 hover、按下和释放命中。

`INFORMATION` 气泡的换行、自适应尺寸、三层背景、混合字体分段位置及相对主宠的锚点/屏幕夹取由 `BubbleVisualDescription` 统一；Qt `Bubble` 和 DX `_DxBubbleWindow` 只注入低级度量、管理队列/生命周期并执行共享批次。DX 的气泡已接入 `INFORMATION`、`TICK`、主宠锚点和 `UI_BUBBLE_HIDE`，真实宿主使用 DirectWrite 低级度量。音响本体的 sprite、动画和 EMA/指数缩放已共享，DX 原生搜索和播放列表宿主已覆盖搜索结果、播放/暂停、队列、进度、音量、播放模式、喜欢和本地音乐操作；不能把 Qt 控件构造到 DX 进程。业务脚本和后端都不得按后端类型选择视觉表现。

## 7. 音乐与本地服务

外部音乐调用只使用 `lib.script.music.get_music_service()`。`MusicProvider` 负责搜索结果标准化，`MusicPlaybackBackend` 定义播放运行时契约，`cloudmusic` 是内部实现。托盘清理历史/登录数据使用 `cloudmusic.user_data` 的无 Qt 数据路径，不得为了清理动作初始化播放管理器；播放器 factory 只能由桌面组合入口注入，Qt 组合可注入 `QtMusicPlayer`，DX 组合必须注入 `None` 并使用既有 MCI fallback。`CloudMusicManager` 不得直接导入 Qt 播放器。

禁止业务模块访问 backend 私有字段、provider 反向导入 MusicService、恢复 cloudmusic 单例兼容入口或运行时改写 `config_music.py`。

办公 DSH 侧车由 `office/runtime.py` 封装进程所有权。启动、发送、停止和清理必须在运行时锁内保持幂等；清理只允许结束当前实例明确持有的 `Popen`，不得扫描或强制结束未知进程。

办公 DSH 侧车源码位于 `services/dsh-office-runtime/`；离线发行包携带固定 Node 运行目录、node_modules 和构建机预生成的 Python 运行时及最小依赖，安装器只负责校验并解压。

音乐登录使用 Playwright 驱动系统 Microsoft Edge，不下载或维护内置 Chromium；页面加载以 DOM 就绪为边界并允许有限重试，登录态仅由音乐 provider 自身保存。

GSV 兼容门面不再启动端口 9880 的 HTTP 服务，而是在原语音工作线程中复用单个 ONNX 引擎。格式版本 2 保留 GPT-SoVITS API v2 参数命名；同一格式内影响正确性的模型或推理升级使用独立 `runtime_revision`，客户端必须拒绝低于当前最低修订的旧包并显示更新入口。语速必须使用 VITS 图内 `speed_factor`，禁止恢复改变音高的最终波形重采样。当前 revision 6 包内置中文 RoBERTa，RoBERTa 加载失败必须报错，不能退回零特征；参考 HuBERT 提示语义必须保留原生链路的尾静音。G2PW 校验只要求 `common/G2P/G2PW/` 中存在非空的 `g2pW*.onnx` 并纳入 SHA-256 清单，不把 `g2pW_int4_fp16mix.onnx` 或任何量化精度文件名作为固定格式；同目录还必须包含原 GPT-SoVITS 的 `polyphonic.rep` 与 `polyphonic-fix.rep`，在整句 G2PW 后按词优先应用。安装器提供完全包、默认中等包和节约包三档，优先 ModelScope、回退 Hugging Face；每档为单个 RAR5 solid archive，使用 64 MiB 字典，安装器优先读取两个公开 resolve URL 的 `Content-Length` 或 `Content-Range`，大小与空间检查使用远端真实值；若用户在列表探测完成前开始安装，安装 Worker 会先对当前档位再次探测，网络不可达时才回退 `VoicePackageProfile` 的离线估算。语音包格式、单文件下载、安装、用户确认删除、旧运行时清理和随包 UnRAR 边界以 `doc/语音包协议.md` 为准。安装前不得为定位旧运行时递归扫描用户目录；安装成功后只清理路径记录明确指向的旧外部 GSVmove。包删除必须由服务在推理锁内释放引擎后执行，并限定在固定磁盘的受管理目录；仓库内 `lib/script/gsvmove/` 不属于删除目标。

ONNX 语音的 CPU 与 GPU 后端都必须在低优先级隔离 Worker 中加载和推理，主进程不得创建模型 Session。自动预热只能在 `APP_MAIN` 后提交，避免模型导入、Session 创建和预热推理与 Qt 首屏初始化争用 GIL 和 CPU。安装依赖固定准备主环境 CPU ONNX 与共享根 `voice/runtimes/onnx-directml/<版本-ABI>` 下的 DirectML venv，不再询问 GPU 方案，也不下载 CUDA。用户进入 AI 设置时才异步检测 NVIDIA 显卡；检测到 NVIDIA 且 CUDA Bundle 尚未通过校验时，在“通用 GPU 加速（DirectML）”下显示“安装N卡推理环境”。独立安装窗口展示加速效果、下载大小、安装占用、临时空间和两个阶段进度，并支持开始与取消。

CUDA 的 **r1** 使用共享根 `voice/runtimes/onnx-cuda/<版本-ABI>` 下的隔离 venv，只接受客户端固定 SHA-256 的专用 Runtime Bundle；Bundle 使用官方 `onnxruntime-gpu==1.22.0`，只保留当前语音真实加载的 CUDA Runtime、cuBLAS/Lt、cuFFT、cuDNN 和 ORT 文件，不携带 Python、开发文件和未加载 CUDA 包。新的 **v2** 使用同一受管根下的独立版本目录，但把 CPython 3.11、ONNX Runtime CUDA、CUDA/cuDNN DLL 和 Worker 全部放进包内；启动时清理系统 Python、venv、Conda、CUDA Toolkit 和用户 PATH，只保留包内路径，唯一主机前提是兼容的 NVIDIA 显示驱动。v2 的格式、Manifest、SHA-256 清单、离线验收和原子激活边界见 `doc/CUDA语音运行时v2自包含方案.md`，不能复用 r1 的格式、哈希或就绪标记。两种版本都必须在外层哈希、内层逐文件哈希、CUDA Session 以及已安装语音包的中英文真实推理全部通过后才原子激活；失败时保持 DirectML/CPU 能力，不得回退或保留未清单化的全量 pip CUDA 环境。混合 Worker 中 `t2s_stage` 走 CPU，其余五个模型图优先 CUDA 或 DirectML；CUDA Worker 中六个模型图都优先 CUDA 并允许 CPU fallback，避免语义迭代解码成为 CPU 瓶颈。CUDA 语义循环使用 I/O Binding 将状态保留在显存，仅同步停止标志，禁止每轮完整状态的 CPU 往返。只有固定 Bundle 静态检查和实际 CUDA Session 探测均有效时，设置页才显示“N卡加速（将提高显存占用）”；关闭时必须终止 Worker 而非只切换 Provider。Worker 在任何 PyQt 导入前预加载 ONNX Runtime，并清除继承环境中的 Qt DLL 路径；v2 模式必须显式加载自有 DLL 目录，不能借用主环境 PyTorch。运行库安装失败属于可降级能力，不阻断 CPU 语音和应用启动。

桌宠正式入口会通过 `lib/script/app/startup_cleanup.py` 后台调用限定路径清理器。清理范围只能是 `<共享根>/voice/runtimes/onnx-cuda/` 的直接子项；保留当前有效 Bundle，删除旧版本、无效的旧 pip 环境、安装暂存目录及 `.part/.zip` 残留，不跟随符号链接或目录联接。

发行版只有统一的 Windows Offline-Installer EXE。它共享清单、敏感配置清洗、官方游戏包及服务 bundle 生成逻辑，并直接携带 Vosk、中英文语音前端和 `resc/GIF/SEanima/` 目录；不携带独立 ONNX 角色语音包归档。`lib/script/gsvmove/bin/UnRAR.exe` 和 `LICENSE-UnRAR.txt` 随包提供，解压器固定校验，不允许安装时联网补取。

根目录 `install_deps.py` 只作为批处理和用户命令的兼容入口；安装实现位于 `install_deps/` 包中。`installer.py` 只负责总编排和历史导入兼容，`catalog.py` 管理静态清单，`console.py` 与 `progress.py` 管理终端输出，`bootstrap.py` 管理 Python/pip 发现，`python_bootstrap.ps1` 管理无 Python 状态下的安装器获取，`dependencies.py` 管理 PyPI 依赖，`voice_runtime.py` 管理 DirectML 环境及 CUDA 构建验证兼容入口，`resources.py` 管理镜像测速、下载、解压和资源安装，`dsh_runtime.py` 管理 DeepSeek Harness 运行时。用户侧 CUDA 安装逻辑位于 `lib/core/cuda_runtime_installer.py`，产品窗口位于 `lib/script/ui/cuda_runtime_installer.py`。依赖安装器在摘要前以单行动态展示“正在检查依赖”的当前包、检查数、百分比和进度条；随后只保留已有/未安装依赖摘要和两条固定安装进度行。支持 ANSI 的终端使用 pip 风格的青色当前依赖、粉色整体进度与暗色未完成轨道，不支持颜色的终端显示等宽单色回退。pip 与 DSH npm 安装进度按可靠输出阶段单调推进；服务端未提供总大小时只显示已下载量与速度，不伪造百分比。下载、解压和依赖安装的条形宽度与字符样式保持一致。整体进度只在一个模块完成后递增。进度刷新不得逐包追加日志。

`安装依赖.bat` 与 `install_deps.py` 的 Python 候选扫描必须排除 uv 管理的基础解释器和 uv 创建的虚拟环境；两者均识别 `EXTERNALLY-MANAGED` 中的 uv 管理声明和 `pyvenv.cfg` 的 `uv` 标记。完全没有可用 Python 时，批处理必须只依赖系统 PowerShell 解析 `resc.net.txt` 的“基础 URL + 文件名”清单，按清单顺序下载固定 Python 3.11 安装器到 `.part`，支持断点续传，并在执行前校验内置 SHA-256；已有安装器同样必须先校验。只发现 uv 环境时应继续安装独立 Python 3.11，不得尝试向带锁环境写入桌宠依赖。

pip 安装调用必须兼容 Python 3.11.6 随附的 pip 23.2.1；每次网络请求使用 30 秒超时和 2 次重试，单次 pip 子进程设置 10 分钟总期限。单个依赖失败后继续安装后续依赖，并在最终摘要中显示对应 pip 错误原因，不能只列失败包名。`ensurepip` 失败后的 `get-pip.py` 获取优先阿里云、回退 PyPA 官方源，并设置显式下载超时。`genie-tts` 依赖的 `jieba-fast 0.53` 在 PyPI 没有 Python 3.11 Windows wheel，安装器必须先从 `resc.net.txt` 的 Gitee/GitHub 镜像下载固定的 `cp311-win_amd64` wheel，校验内置 SHA-256 后本地安装，再安装 `genie-tts`，不得回退到用户机器上的 C++ 源码编译。ONNX 文本前端使用 `opencc-python-reimplemented>=0.1.7,<1`；PyPI 提供 `py2.py3-none-any` 通用 wheel，主依赖安装和语音包补装都必须通过 `--only-binary` 禁止回退源码分发。

主依赖安装后单独创建 DirectML venv，路径和版本由 `config/voice_runtime.py` 统一定义。安装使用同一镜像排序，但必须带 `--no-deps`，避免 `genie-tts` 对 CPU `onnxruntime==1.22.1` 的固定依赖覆盖 DirectML 模块；完成后必须验证 64 位 Python 3.11、ORT 版本和 `DmlExecutionProvider`，再写入 `runtime.json`。

依赖可用性默认同时检查 pip 元数据和实际导入。`genie-tts` 的顶层导入会访问外部 `GenieData` 并产生输出，因此使用 `spec:genie_tts` 做无副作用的模块规格检查；不得因资源目录尚未安装而反复重装同一个 Python 包。

DSH 的用户侧安装只能由根目录 `install_deps.py` 执行。安装器会并发 ping Node 国内镜像与官方源，按平均延迟选择优先下载地址，失败时按测速排序继续回退；下载中断保留 `.part` 并使用 HTTP Range 续传，每个 ZIP 下载完成后必须先通过归档检查和固定 SHA-256，再核对内置 npm 版本。随后并发测速 npmmirror、腾讯 npm 镜像与官方 npm registry，按延迟逐源执行固定 lockfile 的 `npm ci --omit=dev --ignore-scripts --no-audit --no-fund`，并强制将 lockfile 中的 registry host 替换为当前源。Node 已完整但 `node_modules` 缺失或损坏时只重跑 npm。普通 ZIP/WHL 资源也必须在每个源下载完成后验证归档，损坏时删除并切换下一源。应用运行时只校验 Node、npm、profile、bridge、package manifest、lockfile、DSH 入口和必需 RC.6 包，失败时提示重跑“安装依赖.bat”，不得联网、自修复或回退系统上其它 Node 版本。Node/DSH 仅属于办公模式的可选侧车，不是陪伴模式或桌宠核心依赖；当前 DSH 适配层仍以 Node 为官方运行时，Python 原生替代需要另行实现并验收完整的会话、工具和提权协议。

统一发行包携带 DSH 的 `package.json`、`package-lock.json`、profile、bridge 源码、`resc/agent/office_system_prompt.txt` 和随包的十个 `SKILL.md`。办公运行时通过 `DSH_BUNDLED_SKILL_DIR` 挂载 `resc/agent`，但排除 `services/dsh-office-runtime/node_modules/` 与 `resc/node-24.13.0-win-x64/`；构建阶段将 production 依赖和 Node 放入隔离 payload。API key、会话状态和运行时日志不得进入发行包。

发布脚本只允许白名单顶层路径。新增发行文件时必须检查两个入口。`--dry-run` 不下载资源、不写发行包。

桌宠更新器只探测两个固定语音包仓库的 `updates/latest.json`：Hugging Face
`Mark42IRP/Aemeath_onnx_GSV_model` 与 ModelScope `Mark42IRPC/GSV_onnx_Aemeath_Pack`。
两个源应指向同一份已验收程序快照；更新器并发读取清单，优先选择发布时间较新的源，时间相同时
选择响应更快的源。检查阶段不下载文件；用户确认更新后才下载并校验清单指定的
`FlyingSnowVelvet-*-Offline-Installer.zip`，并拒绝 ZIP 内除唯一 EXE 外的其它文件。同 revision
且同 SHA-256 的首选镜像下载失败时可自动切换备用源，revision 或 SHA-256 不同则禁止混用。

固定清单缺失、格式错误、指向不安全路径或 ZIP 校验失败时必须报告发布不可用；不得把模型仓库
源码归档当作更新包。

固定发布槽的 tag 名不是应用版本号。更新状态同时记录 release 时间、源和 revision；只有远端发布时间较新，或时间相同但 revision 改变时才提示更新。下载后的覆盖安装由 `lib/script/app/update_installer.py` 在主进程退出后执行。
