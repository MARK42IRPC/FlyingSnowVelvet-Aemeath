飞行雪绒 Script 开发指南（LTS1.0.6pre8）

一、总览
- 主入口：`lib/core/qt_desktop_pet.py`
- 应用编排：`lib/script/main.py`
- 动态发现：`lib/core/plugin_registry.py`
- 管理器目录：`lib/script/obj-*`
- 粒子目录：`lib/script/practical/*_particle.py`
- 特效目录：`lib/script/effects/*_effect.py`
- UI 目录：`lib/script/ui/`

二、启动与自动发现
桌宠启动时，`lib/script/main.py` 会依次完成：
1. 初始化日志、Qt 运行环境、单实例与快捷方式
2. 加载 GIF 与粒子覆盖层
3. 调用 `discover_all()` 自动发现管理器与粒子
4. 调用 `init_all_managers()` 创建管理器实例
5. 初始化命令框、气泡、托盘、AI 相关组件

扩展开发默认遵循这个发现链路，不需要手动在主入口硬编码注册。

三、管理器开发
推荐位置
- `lib/script/obj-你的模块/manager.py`

基础要求
- 继承 `BaseManager`
- 定义 `MANAGER_ID`
- 定义 `DISPLAY_NAME`
- 定义 `COMMAND_TRIGGER`
- 定义 `COMMAND_HELP`
- 提供 `create()` 工厂方法
- 提供 `cleanup()` 并完成退订、资源释放

当前内置管理器
- `snow_leopard`
- `snow_pile`
- `sofa`
- `mortor`
- `clock`
- `speaker`
- `snowball`

推荐做法
- 需要跨模块通信时，优先发事件，不直接互相引用
- 管理器响应 `#命令` 时，只处理自己负责的范围
- 所有窗口、实体、线程、任务都要在 `cleanup()` 中回收
- 桌面对象资源、创建和几何查询统一通过 `lib.core.world_objects`；管理器只持有不透明图片句柄，并使用核心 `Point/Rect`，不得调用 QWidget 或图片后端的 `geometry()/get_center()/width()/height()`

四、粒子开发
推荐位置
- `lib/script/practical/xxx_particle.py`

基础要求
- 继承 `BaseParticleScript`
- 使用 `@register_particle("particle_id")`
- 定义 `PARTICLE_ID`
- 实现 `create_particles(area_type, area_data)`

粒子实例约定
- 需要 `update()`
- 需要 `alive`
- 建议提供 `life` / `max_life`
- `color`、`font` 使用 `lib.core.graphics.types.Color`、`FontSpec`，不得把 `QColor`、`QFont`、`QPixmap` 或 `QPainter` 放入粒子数据
- 自定义形状通过纯数据字段声明，由 `lib/core/qt_bridge/particle_system.py` 等绘制后端消费
- 可选使用：
  - `is_text`
  - `is_line`
  - `is_circle`
  - `no_fade`

五、特效开发
推荐位置
- `lib/script/effects/xxx_effect.py`

基础要求
- 继承 `BaseEffectScript`，使用 `@register_effect("effect_id")` 注册，并实现 `create_effects()`
- `lib/core/plugin_registry.py::discover_effects()` 会自动发现 `*_effect.py`，无需在主入口硬编码
- 特效脚本只保存文本、资源路径、坐标、颜色、字体参数、时间和动画进度等纯数据状态，不导入 PyQt5 或 `lib.core.qt_bridge`
- 通过 `lib.core.effect_utils.spawn_effect()` 发布 `EFFECT_REQUEST`；图片使用 `resource_path`，不得把 `QPixmap/QImage/QColor/QFont/QPainter` 放入选项或事件 payload
- 图片解码、缩放、羽化和文字效果命令由共享视觉 presenter 负责；后端只负责资源上传、字形栅格化和命令执行

六、输入链路
命令输入框位于 `lib/script/ui/command_dialog.py`

当前输入分流规则：
- `/xxx` → `EventType.INPUT_COMMAND`
- `#xxx` → `EventType.INPUT_HASH`
- 普通文本 → `EventType.INPUT_CHAT`

内置故障恢复命令：
- `#后端 dx`：把持久化绘制后端切换为 `directx`，保存成功后走统一退出链重启。
- `#后端 qt`：把持久化绘制后端切换为 `qt`，保存成功后走统一退出链重启。
- 该实验性入口不依赖控制面板；只修改后端选择，不在命令中心导入或初始化具体绘制后端。

AI 工具调度位于 `lib/script/tool_dispatcher/dispatcher.py`。`STREAM_FINAL.tool_call` 携带已校验的原生 Function Calling 调用时优先执行；没有结构化调用时，才从 `text` 中提取兼容格式 `###指令###`。工具 schema 与映射统一定义在 `lib/script/chat/native_tools.py`。

七、配置项落地链路
如果新增 AI 控制面板配置，至少同步以下文件：
- `lib/script/ui/ai_settings_panel.py`
- `lib/script/ui/ai_settings_storage.py`
- `lib/script/ui/ai_settings_validators.py`
- `config/ollama_config.py`

如果新增普通配置，默认值放到对应的 `config/config_*.py`，用户值通过 `config.user_settings` 保存为稀疏覆盖。禁止运行时修改 Python 配置源码，也不要复制整套默认配置到用户目录。

统一优先级：环境变量/命令行 > `user/settings.json` 稀疏覆盖 > `config` 内置默认值。用户恢复默认时应删除覆盖键。

配置保存边界
- 用户点击保存后，文件写入必须提交到 `ComputeHub.submit_interactive_io()`，不能在 Qt 主线程执行磁盘 I/O。
- 只有后台保存成功，才能继续关闭面板、请求重启或发布 `CONFIG_UPDATED`；保存失败时保留当前界面并显示错误。
- 同一面板的重复点击不能覆盖先提交任务的完成动作，也不能在旧任务完成前启动多次关闭/重启。

麦克风识别
- `lib/script/microphone_stt/` 使用 `webrtcvad-wheels` 按 20ms PCM16 帧判断语音起止；识别模型仍为现有 Vosk，不在录音过程中逐块解码。
- 一句语音收集完成后，Worker 使用 NumPy 频谱软掩蔽降噪，再将完整 PCM 送入 Vosk；`microphone_denoise_enabled` 控制开关，`microphone_denoise_strength` 控制衰减强度，`microphone_noise_gate_threshold` 仅用于无静音参考时选择低响度噪声帧。
- 手动语聊检测到说话后约 0.6 秒静音即结算整句，显式停止也会立即结算；自动语聊保留约 300ms 起始预录和配置的句尾静音保持。
- 降噪后的 Vosk 结果为空时使用原始 PCM 重试；`MIC_STT_FINAL` 仍是聊天提交边界，`MIC_STT_PARTIAL` 不再作为实时识别依赖。

八、运行时数据边界
以下路径视为运行时目录：
- `C:\AemeathDeskPet\user\settings.json`
- `C:\AemeathDeskPet\user\secrets\`
- `C:\AemeathDeskPet\user\state\`
- `C:\AemeathDeskPet\cache\`
- `C:\AemeathDeskPet\logs\`
- 旧版兼容来源：`resc/user/`、`config/music/volume.json`、`config/user_scale.json`

像 GSV 语音缓存这类自动生成文件，应写入统一 `cache/` 目录，而不是可提交源码目录或 `config/`。

更新后的程序由独立 helper 等待旧进程退出后覆盖安装。更新窗口完成下载后显示“更新依赖并重启桌宠”，普通重启使用 `启动程序.bat`，环境重启使用 `安装依赖.bat`；两个入口都在 helper 成功完成覆盖后执行。

九、最小管理器模板
```python
from lib.core.plugin_registry import BaseManager, manager_registry
from lib.core.event.center import get_event_center, EventType


class DemoManager(BaseManager):
    MANAGER_ID = "demo"
    DISPLAY_NAME = "示例管理器"
    COMMAND_TRIGGER = "示例"
    COMMAND_HELP = "[数量] - 示例命令"

    def __init__(self, entity=None):
        self._entity = entity
        self._ec = get_event_center()
        self._ec.subscribe(EventType.INPUT_HASH, self._on_hash)

    @classmethod
    def create(cls, entity=None, **kwargs):
        return cls(entity)

    def _on_hash(self, event):
        pass

    def cleanup(self):
        self._ec.unsubscribe(EventType.INPUT_HASH, self._on_hash)


manager_registry.register(DemoManager.MANAGER_ID, DemoManager)
```
