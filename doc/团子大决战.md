# 团子大决战

更新时间：2026-11-18（绯雪环斩、霜渐与隐藏基准校准）

本文是「团子大决战」官方游戏包的专项协议与落地方案。当前事实源是源码与测试；
文档随实现同步更新。

需求来源：`.oprate/团子大作战.txt`，以及后续补充的「不需要玩家操作，只需选人 + 押注，记录连续押胜」。

## 1. 一句话玩法

两名团子在正方形决斗区里像碰撞球一样自动互撞；团子取自可扩展的角色池，
玩家只做两件事——**选人**和**押注**，然后看比赛、结算战果，统计连续押胜轮数。

## 3. 阶段流

```text
select（选人 + 押注） → fight（自动战斗） → result（本轮结算）
                           ↑                    │
                           └── 未完赛，3 秒后 ──┘
系列赛结束：result（最终结算） → 玩家返回 → select（新系列赛）
```

- 每个系列赛只在开始前选人和确认押注。未决出系列赛结果时，本轮结算卡展示 3 秒（`AUTO_ADVANCE_SECONDS`）后直接进入下一轮战斗，并播放正常开场倒计时。
- 同一系列赛沿用左右双方团子、押注侧和押注金额；新一轮重置双方生命、技能、位置与速度及上一轮特效，保留系列赛比分、连续押胜、当前筹码和历史战绩。筹码可为负数，不因此中断系列赛。
- 自动倒计时、结算卡「下一轮」按钮与 `R` 共用同一续局入口；揭卡后的 `R` 或按钮可提前开始。系列赛结束后保留最终结算卡，点击「返回选人」或按 `R` 才回到选人，不跨系列自动重开。
- 续局统一由 `DangoMatch.advance_round()` 承接；每轮仍正常发布开赛、伤害与结算事件。揭卡时间与结算卡倒计时分别计时，同一帧跨越边界时不重复消费时间。
- 轮次按本系列赛计数，成功开赛时递增；新系列赛重新从第 1 轮开始，累计历史轮数独立保存。
- 关闭窗口沿用游戏宿主 `GameRuntimePanel` 的关闭按钮与 `set_close_callback`。

## 4. 界面布局

整体画布采用硬朗的科幻几何风格：深海军蓝渐变底、细蓝图网格、斜切面板、切角（chamfer）边框、
发丝级高光描边；顶部指挥条 + 中部三栏（左右团子卡 + 正方形决斗区）+ 底部状态条。
虚拟画布固定 1080×720（3:2），按窗口等比缩放并居中，多余区域露出渐变底。
视觉令牌集中在 `constants.py`（主色盘见 6.3），布局与 `DrawBatch` 构造集中在 `presenter.py`，不与逻辑混写。

```text
┌────────────────────────────────────────────────────────────┐
│ 团子大决战  第 N 轮 · 五轮三胜   连续押胜 | 最高 | 筹码  关闭│
├────────────┬─────────────────────────────┬─────────────────┤
│ 1P 团子卡  │                             │ 2P 团子卡       │
│ 头像 名称  │      正方形决斗区            │ 头像 名称       │
│ 生命 180   │   （纯黑底 + 标志水印）      │ 生命 260        │
│ 量槽 命中  │   团子精灵 + 技能贴图        │ 量槽 命中       │
│ 胜场圆点   │   撞击抖屏 / 受击闪红        │ 胜场圆点        │
├────────────┴─────────────────────────────┴─────────────────┤
│ 底栏：状态提示 / 总轮次与押注战绩 / 双方生命与命中摘要       │
└────────────────────────────────────────────────────────────┘
```


- 决斗区是正方形：边长 `side = min(可用宽, 可用高)`，在中间列垂直居中；场内只有纯黑底（`C_ARENA`）与一张低透明度标志水印，不绘制网格、准星、菱形等其它图形。
- 左右面板等宽，随窗口等比缩放；manifest 最小窗口 810×540，两种尺寸均验收过无越界、无文字重叠。
- 选中态用抬升面板 + 侧边强调条、`1P` / `2P` 斜切徽标与「押注方 / 决斗者」状态字建立层级；角色矩阵超过单页容量时提供翻页按钮与页码，所有已加入角色都可选择，不仅显示剩余数量。
- 左右面板数据：头像、名称、标签（如「星辉团子」「虚质团子」）、技能量槽、当前生命与生命条、胜场圆点、命中/受击统计；生命条与生命数字统一使用亮红 `C_HP_FILL` / `C_DAMAGE`（`#FF404E`），不按阵营换色，生命扣减只走这一种红色。
- 顶栏：标题、系列赛轮次与赛制（`第 N 轮 · 五轮三胜`）、等宽三格统计（连续押胜 / 最高 / 筹码）、关闭按钮。
- 界面文字全部中文；排版统一粗体 + 大号（标题 28~34、团子名 24、关键数字 32~36），单行超宽走 `_fit_text` 缩字，段落走 `wrap_lines` 显式分行，保证不溢出、不叠字。

### 4.1 选人阶段

- 采用拳皇式选人：上方是双方角色预览与押注指挥台，下方完整宽幅区域专门展示多行角色矩阵；角色列表是主要选人区域，不与步骤说明挤在底角。预览卡保留头像、角色配色、`1P` / `2P`、押注状态、初始生命与技能信息。
- 预览卡内部按共享度量表排列头像与身份、生命信息，技能说明和底部胜场各有独立区域，避免挤压矩阵或覆盖文字。
- 中间是独立的指挥台：对决标题、当前押注方、赔率说明、筹码 `1 / 5 / 10`、当前筹码池、系列赛连续进行提示与开始按钮；生命信息归各自角色卡，文字与按钮按区块落位，不覆盖卡片。
- 团子矩阵在默认与最小窗口均为 12 列 × 3 行，每页 36 位，格子保持正方形；未加入角色的格子只是预留空位，没有解锁规则或虚构角色。列表头部展示名称、操作提示、赛制与分页，底部展示数量及当前编辑的侧别。唯一的「开始对决」按钮保留在中央指挥台。
- 矩阵布局及页容量由 `presenter.roster_grid_layout()` 统一计算，`roster_page_count()` 给出当前页数。窗口只保存当前 `roster_page`，鼠标翻页与 `PageUp` / `PageDown` 使用同一边界钳制；增减团子池后也不会停留在不存在的页。页码不写存档。
- 团子池由 `roster.py` 的 `ROSTER` 驱动；新增团子只需追加一条 `DangoEntry` 并放入 `assets/dango/<character_id>/{idle,attack,hurt}.png`，不在战斗代码里写死双方。
- 点击顶部角色卡 = 押注该侧；点击团子格会替换当前押注侧的团子，网格与预览同步更新。`1P` / `2P` 徽标只表示已选身份，不会因点击对方已占用角色而悄悄切换押注侧；双方重复选同一角色仍按现有规则拒绝。
- 选边与选筹码都完成后「开始对决」才可点击，按钮文案会给出下一步提示；`R` 键随机双方与筹码；`F1` / `F2` / `F3` 切换赛制「五轮三胜 / 三局两胜 / 一决死战」。
- 选人界面的存档记录（连续押胜 / 最高 / 筹码）为等宽三格，字号统一，不叠字。
- 角色 ID 从实际比赛快照传入，随机到左右交换时，海报、名单标记与开赛后的团子身份一致。头像使用共享的连续轻呼吸（面积守恒伸缩与不超过 1.5 px 浮动），通过分数仿射变换绘制，避免精灵整数坐标导致长时间不动后跳像素；使用暂停时冻结的呈现时钟，不消费比赛随机数。
- 精灵局部尺寸保持固定，后台解码与 pixmap 缓存不随呼吸反复生成。静态蓝图背景与空位命令使用有界缓存；帧驱动使用 16 ms 精确 Qt 定时器，实际帧时间仍取决于机器负载。
- 团子不参与操作，只按物理规则自动碰撞。

### 4.1.1 系列赛（赛制）

| 赛制 | 轮数 | 判定 |
| --- | --- | --- |
| 五轮三胜（默认，`bo5`） | 最多 5 轮 | 先赢 3 轮即结束 |
| 三局两胜（`bo3`） | 最多 3 轮 | 先赢 2 轮即结束 |
| 一决死战（`bo1`） | 1 轮 | 一轮定胜负 |
| 死战三局（`ft3`） | 3 轮 | 打满 3 轮，总胜场多者获胜（平局计入但也算打满） |

- 赛制只在系列赛开始前可改；系列赛进行中按钮锁定，结束后回到选人可重新选择（换赛制会重置比分）。
- 双方卡片下方用圆点显示已赢轮数；顶栏中央显示 `第 N 轮 · 赛制名`。

### 4.2 押注

- 押注对象：左/右团子之一（与选人侧关联）。
- 押注额度：三档固定筹码 `1 / 5 / 10`，结算时净增或净减押注额，平局净变化为 0；开赛时不预扣，因此当前筹码可为负数。新存档初始筹码为 1。
- 押注赔率：固定 1:1。
- 确认押注后进入 `fight`；未押注不得开赛。
- 押注只是「赌哪一方赢」，不影响团子属性或速度，保证比赛公平。
- 押注在整个系列赛内沿用，逐轮独立结算且每轮只结算一次；系列赛结束后返回选人才清空押注，新系列赛需要重新选边和筹码。

### 4.3 结算阶段

- 展示胜者（团子名字，只用 `1P` / `2P` 标记侧别）、系列赛比分、押注结果、筹码变化与当前筹码、本局撞击数、剩余生命、本轮用时、连续押胜。
- 三类押注结果都纳入正式结算：

| 结果 | 触发 | 结算文案 | 连押 | 音效 |
| --- | --- | --- | --- | --- |
| 押中 | 押注侧即胜者 | 押中 {团子名} · 筹码 +N · 连押 M | `streak + 1`，更新最高，筹码 +N | `win`，连押≥2 追加 `streak` |
| 押错 | 押注侧输 | 押错 {团子名} · 筹码 −N · 连押清零 | `streak = 0`，筹码 −N | `lose` |
| 平局 | 双方生命同时归零（正常对撞下即双方同步扣血） | 平局 · 筹码不变 · 连押保持不变 | 保持不变 | `draw` |

- 平局单独累计 `total_draws`，不写赢/输计数；未押不会出现（未押不能开赛）。
- 结算面板自上而下：本轮/系列赛结束、胜者、`赛制 · A x : y B`、押注行、六行数据（本局撞击 / 剩余生命 / 本轮用时 / 连续押胜 / 筹码变化 / 当前筹码），全部排在按钮上方，按钮下方只有一行提示。
- 押注的团子始终排在结算文案第一位，左右只体现在 `1P` / `2P` 徽标上。
- 游戏结束时团子停止运动，失败方保持「受伤」图片并被压扁；3 秒后才弹出结算界面。
- 结算延续「团子出击」，不追加独立胜利 BGM。
- 按钮显示实际剩余倒计时「下一轮 N 秒」（系列赛结束后为「返回选人」），进度条与同一计时状态同步；点击与 `R` 都会立即进入下一轮战斗。

## 5. 战斗规则

### 5.1 基础数值

生命、普通碰撞攻击与团子专属技能规则由 `roster.py` 驱动；每次有效球球撞击
双方各结算一次普通攻击，场地边界只反弹并轻微扰动方向，不直接造成伤害。技能可以造成
单侧伤害并改变受击方向；通常转向保持速度大小，星爆将目标暂时停在底部中央再恢复暂存动能，
绯雪环斩命中则对目标施加 3 秒的 50% 减速。

| 项目 | 数值 | 来源 |
| --- | --- | --- |
| 初始生命 | 爱弥斯 180；达妮娅 260；西格莉卡 185；绯雪 165 | `roster.py:DangoEntry.max_hp` |
| 默认普通攻击 | 1；双方在一次有效接触中各攻击一次 | `DangoEntry.contact_damage`，默认沿用 `DAMAGE_PER_IMPACT` |
| 隐藏测试基准 | 生命 500，无技能；每次有效攻击独立均匀取整数 1–5，均值 3 | `roster.py:BENCHMARK_ENTRY` |
| 有效撞击门槛 | 法向相对速度 ≥ 0.05 | `MIN_IMPACT_SPEED` |
| 场地边界碰撞 | 只反弹并轻微扰动方向，不减生命 | `WALL_JITTER_DEG` |
| 结算条件 | 双方生命同时归零时判「平局」（`double_ko` / `draw`） | `CombatTracker` |

团子按物理轨迹自动运动；普通攻击随有效碰撞结算，专属技能还可由固定战斗计时触发。

西格莉卡（`xigelika`，「日灵团子」）初始生命 185，使用双色日灵技能，规则见 5.4.1。
绯雪（`feixue`，「霜渐团子」）初始生命 165，使用环斩与霜渐技能，规则见 5.4.2；
生命已按本轮冻结技能完成隐藏基准候选选择及独立验证，不沿用旧无技能结果。

### 5.2 伤害判定（一次性接触）

- 接触判定：圆心距 ≤ 两半径之和。
- **每次接触只结算一次伤害**；必须等圆心距 > 两半径之和 + 分离余量
  （`SEPARATION_MARGIN = 0.012` 虚拟单位）后，才允许下一次结算。
- 避免两球擦边停滞导致每帧扣血。
- 同帧内多物体只处理团子 A/B 一对；不引入第三方物体。
- 普通攻击读取攻击方的 `contact_damage` / `contact_damage_range`。声明范围时，每次有效攻击
  由比赛 RNG 独立取样一次；默认固定 1 点不额外消费随机数。双方伤害在同次接触中结算，
  不因一方先被扣至零而取消另一方已经发生的攻击，双 KO 仍按平局处理。

### 5.3 物理模型

- 2D 圆形刚体，等质量，纯 Python 实现（`physics.py`，不依赖 Qt）。
- 固定步长积分（60 Hz），累计时间驱动，避免不同帧率下行为漂移。
- 撞墙扰动不使用进程全局计数；技能随机角度来自比赛 RNG，虚手贴图旋转使用独立视觉 RNG。同一 seed 的纯比赛在 30 / 60 / 120 FPS 下可重放相同结果与技能事件。
- 自由飞行：匀速直线运动；没有导向力、拉近、追人、停滞恢复或额外加速。
  `Ball.vx` / `vy` 与 `speed` 保存原始运动量；`motion_multiplier` 控制实际位移，
  `movement_speed` 为原始速度乘位移倍率，环斩减速不反复乘除原始速度。
- 圆-圆碰撞：未减速时为等质量弹性碰撞，法线方向交换速度分量，切线速度保留。
  不同位移倍率时使用加权法向反射，反转实际相对法向速度并保持原始速度平方和，
  避免同向追撞被误判为分离或减速状态造成原始动能持续流失。
- 边界反弹：法线分量取反，并把结果方向旋转一个很小的随机角
  （`WALL_JITTER_DEG = 3`）；原始速度大小与当前位移倍率保持不变。
- 初始速度：`LAUNCH_SPEED_RANGE = (0.85, 1.0)`，仰角限制 `±38°`；
  左右镜像出生，单纯用于提供可玩的自动对撞节奏。
- v1 不设超时判定：比赛在自然碰撞与双方同步扣血下结束；不额外增加计时器或保底收敛规则。

### 5.4 团子专属技能（数据驱动）

`roster.py` 的 `DangoEntry.meters` / `collision_rules` / `sun_spirit` / `frost_slash` 是技能唯一事实源；
`skills.py` 只读取规则，不写角色分支。

| 角色 | 技能 | 触发与数值 |
| --- | --- | --- |
| 爱弥斯 | 星能激光 | 团子对团子碰撞 +1 星能；满 3 格发射 8 点激光，清空后 +1 星爆；激光只朝经过目标中心的方向发声，不会在窗口中心留下横向白条 |
| 爱弥斯 | 星爆 | 满 4 星爆造成 60 点全屏伤害，随后清空；敌方团子被重置到决斗区**底部中央**，并爆出大量蓝/青/白爆裂粒子 |
| 达妮娅 | 虚空之手（虚质团子） | 每次团子碰撞或撞墙都有 50.5% 概率召出虚手，伤害在 **1~4 点之间随机浮动** |
| 西格莉卡 | 双色日灵（日灵团子） | 每次有效团子碰撞攻击随机积攒黄/青能量，撞墙另有 50% 概率获得一枚随机颜色能量；共享 4 格，满槽再次获得能量改为两色当前冷却各减 1 秒；消耗 2 枚同色召唤日灵，两色各自独立 5 秒冷却，冷却结束才消耗；1 秒后范围爆炸 28 点，青色再隔 0.45 秒扩圈爆炸 14 点 |
| 绯雪 | 环斩与霜渐（霜渐团子） | 每 3 秒以自身为中心进行半径 0.286 的环斩；命中造成 30 伤害并减速 50%、持续 3 秒；未命中获得 1 枚霜渐能量，最多 4 枚；每次有效身体攻击消耗 1 枚能量附加 2 伤害 |

  使用已有粒子脚本，统一交共享场景与 `DrawBatch` 绘制。

  总时长 `STARBURST_EFFECT_SECONDS = 1.0`，最后 0.18 s 渐隐。

  延后到落地帧，与大幅震动、场内粉白闪光、桌宠既有爆发线粒子、0.07 s 顿帧

  `C_DAMAGE`（`#FF404E`）。
- 激光事件携带 `angle` 与经过目标中心的 `start` / `end`；星爆事件携带

### 5.4.1 西格莉卡：双色日灵

- `DangoEntry.sun_spirit` 使用纯数据 `SunSpiritSpec`：`slots=4`、`cost=2`、`wall_chance=0.5`、`cooldown=5.0`、
  `overflow_cooldown_reduction=1.0`、`delay=1.0`、`second_delay=0.45`、`radius=0.162`、`second_radius=0.27`、`damage=28`、`second_damage=14`。
  半径以正方形决斗区边长为 1 的归一化坐标表示，伤害与计时由纯规则层决定。
- 每次有效团子碰撞视为双方各攻击一次；未满四格时，西格莉卡用比赛 RNG 等概率获得黄色或青色能量。
  每次真实墙壁碰撞由物理 `wall_hits` 路径独立判定，另有 50% 概率获得一枚能量，成功后黄/青仍等概率。
  技能命中与日灵爆炸不额外充能；共享四格存满时再次成功获得能量，不增加或覆盖颜色，改为缩短冷却。
  撞墙概率来自 `SunSpiritSpec.wall_chance`，不在物理层或渲染层写角色分支，也不按墙边停留帧重复判定。
- 满槽获得能量时，黄色、青色此刻正在冷却的日灵 CD 各减 1 秒，最低为零；两色先各处理一次，
  再检查库存，减到零且有两枚同色能量就立即消耗并召唤。该次召唤新开的 5 秒冷却不再被同一次获得能量扣减。
  身体有效攻击必定触发一次获得能量；墙壁只有 50% 判定成功才触发，失败不减 CD。
  未满四格时仍正常添加一枚随机颜色能量，不缩短冷却。
- `Dango.sun_energy` 按获得顺序保存 `yellow` / `cyan`；`sun_cooldowns` 分别保存两色剩余冷却秒数。
  任一颜色至少有两枚且该色冷却为零时，自动消耗两枚该色能量，在敌人当时的位置召唤对应日灵，
  并从召唤瞬间开始该色的 5 秒冷却。该色召唤本身不改变另一颜色的能量与冷却。
- 冷却期间同色能量保留且可继续积攒；到期后自动检查并施放，不需要等下一次攻击。
  冷却未结束时不能提前消耗能量或提前召唤。
- 黄色日灵使用原 `日灵1.png`，青色日灵使用原 `日灵2.png`。日灵固定在召唤点，不跟随敌人移动。
  召唤 1 秒后首爆半径 0.162、伤害 28；青色首爆后再等 0.45 秒，在同一点以半径 0.27 二爆，伤害 14。
- 每次爆炸独立检查敌人当前的圆形碰撞体是否与爆炸圆相交；离开范围可躲过该次伤害。
  即使首爆未命中，青色仍会进行二爆；同一阶段不会因持续显示画面而重复扣血。
- 延时与冷却在比赛固定步长内推进，选人、开局倒计时、暂停及结算期间不推进。
  每轮开赛重置能量、两色冷却及待爆日灵，上一轮未触发的爆炸不会进入下一轮。
- 规则通过 `sun_spirit_summon` / `sun_spirit_burst` 通知表现层；日灵贴图复用共享图片效果，
  爆裂光点与碎片复用既有粒子。蓄爆范围圈和冷却刻度属于游戏预警界面，仍由 presenter 构造；
  可躲避的爆炸范围与画面预警使用同一归一化半径。

### 5.4.2 绯雪：环斩与霜渐

- `DangoEntry.frost_slash` 使用纯数据 `FrostSlashSpec`：`interval=3.0`、`radius=0.286`、
  `damage=30`、`slow_seconds=3.0`、`slow_multiplier=0.5`、`energy_slots=4`、
  `contact_bonus=2`、`energy_per_contact=1`。半径以决斗区边长为 1 的归一化坐标表示。
- 首次环斩在本轮实际战斗推进满 3 秒后触发，之后每 3 秒施放；环斩以施放者当时的位置为中心，
  目标当前圆形碰撞体与半径 0.286 的范围相交时命中。离开范围可躲避，不跟踪目标或改为全屏伤害。
- 命中造成 30 点伤害，并将存活目标减速至 50%，持续 3 秒。再次命中刷新为 3 秒，
  不将倍率叠乘到 25% 或更低；到期移除这次临时减速。命中不会同时获得未命中的能量奖励。
  减速以位移倍率作用于运动，不修改原始 `vx` / `vy` 或星爆暂存的原始速度平方；
  墙反弹、技能转向及星爆动能返还均保留当前倍率，避免绕过减速或重复降低原始速度。
- 未命中获得 1 枚「霜渐」能量，共享四格，满格后不覆盖或继续增长。
  每次有效身体碰撞攻击在有能量时消耗 1 枚，为本次普通攻击附加 2 点伤害；
  基础攻击仍为 1，霜渐附伤计入同次身体攻击，双方伤害仍同时结算。
  持续接触、无效擦碰、撞墙及技能伤害均不重复消耗能量。
- `Dango.frost_elapsed` / `frost_energy` 保存施放计时与库存，目标的 `slow_seconds` /
  `slow_multiplier` 保存当前减速状态。计时由比赛 60 Hz 固定步推进，选人、开局倒计时、
  暂停、隐藏及结算不推进；新轮重置施放计时、霜渐库存与减速，上一轮状态不进入下一轮。
- `frost_slash` 事件同时报告命中与未命中，画面依据真实规则事件播放刀光；
  主体复用桌宠既有 `smooth_image_show`，刀尾与命中反馈复用既有 `star_streak` / `burst_line`，
  统一经局部 `FeedbackScene` 与决斗区裁剪绘制。游戏包只提供刀图、参数和技能预警界面，
  不新增私有粒子运动算法或特效运行时。
  斩击在 0.06 秒内完成整圈，先以强白青刀光瞬时爆发；刀体与闪光在 0.12 秒内消退，
  弧形残影在 0.52 秒内消散，旋转完成后不会随残影继续慢转。
  弧光与花瓣同样作为共享图片效果实例；
  `rotation` / `angular_velocity` / `angular_duration` / `orbit_offset` / `orbit_start_angle` 的旋转与轨迹计算属于宿主图片效果，
  widget 只同步施放者锚点，不实现另一套刀图运动器。未命中仍完整挥刀，命中才显示实际伤害与减速状态。
  飘雪使用宿主共享注册脚本 `frost_snowflake`：每次请求 14 枚，寿命 0.55–0.85 秒，
  速度 35–90 像素/秒，直径 8–14 像素；六臂雪花由共享绘制批次交给 Qt/DX，
  包内不复制雪花运动或绘制类。视觉 seed 来自独立 `_visual_rng`，不消费比赛 RNG。

### 5.5 团子状态机

```text
idle ──碰撞瞬间──> attack（0.5 s 或被受击打断） ──> idle
idle ──受到伤害──> hurt（0.3 s，闪红） ──> idle
```

- `idle`：常态图，慢速呼吸式拉伸（低频、小幅度）。
- `attack`：使用「攻击」图片，持续 `ATTACK_SECONDS = 0.5` 秒，或被受击打断，然后回到常态图。
- `hurt`：使用「受击」图片并叠加红色染层闪烁，持续 `HURT_SECONDS = 0.3` 秒（闪红 `HURT_FLASH_SECONDS = 0.3`），保证肉眼可辨，再回到常态图；死亡后停在「受击」图片。
- 普通撞击与技能伤害都进入受击状态；红色染层的明暗交替不切换基础受击图片。命中/受击统计包含导致 KO 的最后一次技能。
- 三种状态的拉伸「频率 / 幅度 / 持续」参数集中在 `constants.py`，可单独调。
- 受击闪红通过 `RasterFrame` 的着色缓存实现（纯 Python 颜色混合），不依赖 Qt 图像 API。

### 5.6 隐藏平衡基准与离线校准

- `BENCHMARK_ENTRY` 是仅供无界面测试使用的基准：生命 500，没有量槽、反应、碰撞技能、
  日灵或环斩规则。每次有效团子碰撞中，它独立均匀抽取 1–5 点整数作为本次普通攻击，均值为 3；
  撞墙不攻击，也不随时间主动造成伤害。它与普通团子使用同一半径、质量、出生和速度规则，
  不是第三个碰撞体，没有额外追踪、减速或克制技能。
- 基准独立于公开 `ROSTER`，不出现在选人矩阵、随机名单、公开角色分页或角色素材加载中，
  也不新增窗口、技能页或图片。仅无界面校准入口可将它作为一侧对手交给真实 `DangoMatch`。
- 校准复用正式的 BO1、60 Hz 固定物理步、正常开场倒计时、伤害、技能、KO 和单次结算路径；
  不用平均攻击替代随机取样，不另建胜负模型，也不为基准写星爆或物理特殊分支。
  随机数来自比赛 RNG，记录种子并均分左右侧；存档与结果文件写入隔离位置，不改用户战绩。
- **平衡分**为 `(胜场 + 0.5 × 平局场) / 总场数`，目标区间为 **47.5%–52.5%**。
  原始胜率仍单独报告，不能把半平局分数称为原始胜率；无平局时两者才相等。
  爱弥斯、达妮娅、西格莉卡保留既有校准值；绯雪本轮新增环斩与霜渐后完成校准，
  正式生命为 165。四名公开角色的正式生命均取 5 的倍数。
- 包内 `balance.py` 提供共享无界面校准能力，`scripts/simulate_dango_balance.py` 提供命令行入口。
  命令参数包括 `--character`、`--mode thresholds|verify|theory`、`--hp`、`--hp-step`、`--count`、
  `--start-seed` 和 `--out`。阈值探索、指定生命复核与长期抽样必须使用同一正式引擎；
  探索结果不直接当作正式生命值，候选值还需以独立种子验证。
- `thresholds` 用足够高的探针生命保持参与者存活，记录基准死亡时累计所受伤害及最后一次身体攻击前
  的伤害前缀，在允许的生命网格中选择最接近 50% 平衡分的最小生命。CLI 的 `--hp-step` 默认 5，
  因此候选为 5 的正整数倍；包内 `choose_hp(rows, step=1)` 保留逐整数探索的默认行为。
  探针结果只是训练候选，必须以同种子实际生命
  重放检查胜/负/平预测，并另外使用未参与选择的种子验证，不能把拟合分数当作已验收结果。
  伤害前缀推断的前提是死亡前的技能计时、库存、减速、轨迹和随机数消费不依赖候选生命，
  也没有低血量反击等影响战斗的机制。环斩虽会改变轨迹，仍须检查上述生命独立性，
  并用真实生命重放核对，不能直接把旧无技能绯雪的接触数或样本沿用到新技能。
  `verify` 使用真实候选生命进行正式对局；省略 `--hp` 时使用角色当前配置，提供 `--hp` 只覆盖本批模拟，
  不改公开名单或源码。`--hp-step` 只约束阈值候选，不限制 `verify --hp` 的正整数实验生命。
  `thresholds` 禁止同时传 `--hp`，模拟的 `--count` 必须为正偶数以均分左右侧。
- `theory` 只适用于满足确定伤害序列前提的配置，当前公开角色中仅爱弥斯符合；
  使用独立均匀 1–5 攻击的精确整数卷积，给出胜/负/平
  与平衡分；它不模拟另一套物理，终止接触数与技能先后顺序仍由真实引擎重放验证。
  已配置环斩的绯雪必须拒绝旧无技能理论入口：其范围命中、减速与霜渐附伤取决于实际轨迹，
  与达妮娅、西格莉卡一起使用正式引擎抽样，不把近似均值模型或旧 500 接触公式称作精确理论值。
- 报告保留有效参数、全部种子、左右侧、胜/负/平、平衡分、原始胜率及不确定性说明。
  抽样平衡分使用 0 / 0.5 / 1 分数的样本方差给出 95% 正态近似区间，明确区别于二项胜率 Wilson 区间。
  保护上限只用于报告未自然完赛的失败样本，不能将其记成平局、跳过种子后宣称合格，
  或给正式比赛增加强制超时胜负。长期估计不保证每一个 100 局批次都落入目标区间。

复现入口（结果写入隔离文件；以下命令不更改角色生命配置）：

```powershell
py -3.11 scripts/simulate_dango_balance.py --character xigelika --mode thresholds --hp-step 5 --count 200 --start-seed 30000 --out cache/dango-balance/xigelika-thresholds.json
py -3.11 scripts/simulate_dango_balance.py --character xigelika --mode verify --count 2000 --start-seed 50000 --out cache/dango-balance/xigelika-verify.json
py -3.11 scripts/simulate_dango_balance.py --character amis --mode theory --out cache/dango-balance/amis-theory.json
```

`verify` 使用探针候选时须显式传入 `--hp`；训练种子与最终复核种子分开记录。
`--max-sim-seconds` 默认 10000，仅为实验进程的失败诊断保护，不属于游戏胜负规则。

## 6. 视觉表现

### 6.1 绘制通道（不直接导入 PyQt5）

官方游戏包 v1 允许 `widget.py` 使用 Qt；本包在此基础上进一步收敛：

- **业务与布局层不导入 PyQt5**，也不导入 `lib.core.render.backends.qt`。
- 所有画面由后端中立的 `DrawBatch` 命令组成（`SpriteCommand` / `RectCommand` / `EllipseCommand` /
  `LineCommand` / `TextCommand`），由 render 层执行：
  - 静态/动画帧：`lib.core.render.visuals.image_loader.load_image_resource` + `resize_image_resource`；
  - 资源与帧：`lib.core.render.visuals.scene.DrawScene`；
  - 批次：`lib.core.render.visuals.commands.DrawBatch`；
  - 执行：`lib.script.ui.render_bridge.create_painter_host()` → `QtPainterHost.render(batch, painter)`。
- `lib/core/services/feedback_scene.py` 提供共享场景与实例生命周期；Qt/DX 桌面覆盖层和游戏
  共用粒子、特效对象的创建、更新及插值逻辑。游戏只注入已有注册表管理器，不复制粒子算法。
  `spawn_particle` / `spawn_effect` 复用已注册脚本，`advance` 驱动场景；输出继续使用
  `build_particle_batch` / `build_effect_batch`，由游戏的决斗区裁剪和画布变换承接。
- **资源在后台异步加载**：`assets.py` 的 `DangoAssetLoader` 用守护线程预解码团子各状态帧、
  受击染色帧、星爆 GIF、日灵、激光与绯雪刀图；`widget.__init__` 只启动线程（约 0.5 ms），
  `_on_tick` 每帧检查结果并一次性装入精灵表。实测解码约 300 ms，不再阻塞窗口出现。
  `ImageResource` / `RasterFrame` 都是冻结值对象，跨线程交付无需加锁；只有结果快照有锁。
- 普通绘制的水印、虚手、日灵与刀图资源查询只读取后台加载快照，不等待线程；新一轮会清空上一轮的激光、虚手、星爆、日灵、刀光、闪光与延迟数字。
- 暂停、隐藏时不推进局部反馈场景；续局、重置、关闭与停用时只清理本游戏场景，不清空桌宠全局
  覆盖层。伤害数字与其目标坐标在同一局部空间内，避免负原点多屏时漂移到错误目标。
- 宿主 `widget.py` 只保留最小窗口胶水：`QWidget` 生命周期、`paintEvent` 里取得 painter、
  `QTimer` 帧驱动与鼠标事件转发。它不画图、不改颜色，不持有主题。
- 可选进一步收敛：若项目提供可复用的「游戏画布宿主」，`widget.py` 只做 `QWidget` +
  注入渲染回调，避免一切 PyQt 导入。实现前先核对 `lib/core/render/backends/qt/widgets/`
  是否已有可复用宿主；没有则不新增通用宿主，保持本包内最小胶水。

- 游戏通过可选 `set_bgm_callback(callback)` 向宿主报告 `(歌名, 作者, track_ref=...)`，不创建独立播放器。两首优先使用用户提供的网易云 ID（`netease:ID`），无需搜索；官方标题分别含「……」和「！」，不依赖标题标点匹配。setter 绑定后立即报告当前界面；同一阶段、系列内续局和逐帧刷新不重复请求同一首，返回选人才切回准备曲。
- `manifest.bgm_keyword` / `bgm_artist` 保持空，由动态回调指定两首；不支持此钩子的旧游戏仍沿用 manifest 静态 BGM。
- 宿主复用 `MusicService` 和桌宠共享音乐队列：有直接 ID 时跳过搜索；未提供 ID 的旧请求精确匹配歌名、作者。按用户要求，动态 BGM 每次切换目标时先清空队列，再仅加入当前歌曲；共享播放器以单项队列自动循环，战斗曲播完不会轮到准备曲。同一阶段和系列内续局不重复清空或从头播放。
- 搜索使用 `ComputeHub` 后台 IO，完成结果在宿主主线程 TICK 处理；切换阶段、关闭、重开后过期搜索、入队及播放命令无效。退出仅暂停当前仍属游戏的音乐，保留当前单项队列及正常播放进度，不误停用户后来换播的其他歌曲；下载或播放器待启动时退出也保持暂停，不会迟到自动播放。旧阶段的缓存查找和下载任务也按播放代次作废。
- 结算延续战斗曲，不追加独立胜利 BGM。

## 8. 事件与扩展接口

### 8.1 对外事件（包内定义，供后续技能/特效/语音扩展消费）

以下事件通过 `get_event_center().publish(Event(事件名, 载荷))` 发送纯 Python 载荷；
v1 不新增全局 `EventType`，避免改动核心协议。事件名统一前缀：

| 事件名 | 载荷 | 触发时机 |
| --- | --- | --- |
| `dango_showdown.match_start` | `round, left_id, right_id, bet_side, bet_amount` | 开赛 |
| `dango_showdown.hit` | `side, speed, hp_left, hp_right, point, normal, damage_left, damage_right` | 每次有效撞击结算生命；末两项按左右记录实际承伤，兼容旧构造时默认各为 1 |
| `dango_showdown.ko` | `winner, loser, hp_left, hp_right, hits, draw` | 出现胜者（平局时 `winner`/`loser` 为空、`draw=true`） |
| `dango_showdown.bet_settled` | `bet_side, winner, hit, draw, streak, best_streak` | 结算押注；押中 `hit=true`，平局 `draw=true` 且 `hit=false` |
| `dango_showdown.match_end` | `winner, duration_ms, stats` | 结算界面出现 |
| `dango_showdown.charge_changed` | `side, meter_id, label, value, slots, source, colors` | 能量格变化；日灵 `meter_id=sun_energy`，`colors` 按槽位顺序列出颜色；霜渐为 `frost_energy`，无颜色的量槽默认空元组 |
| `dango_showdown.laser_fire` | `side, target, damage, hp_left, hp_right, start, end, angle` | 激光发射（方向随机、过目标中心） |
| `dango_showdown.starburst_fire` | `side, target, damage, hp_left, hp_right, impact_ms, total_ms` | 星爆发射（2 倍速：落地帧 910 ms / 总 1000 ms） |
| `dango_showdown.void_hand` | `side, target, source, damage, hp_left, hp_right, point` | 虚空之手触发 |
| `dango_showdown.sun_spirit_summon` | `side, target, color, point, radius, delay, second_delay, second_radius, summon_id` | 消耗两枚同色能量并召唤日灵；`point` 是固定出生点 |
| `dango_showdown.sun_spirit_burst` | `side, target, color, point, radius, stage, damage, hit, summon_id, hp_left, hp_right` | 日灵各阶段爆炸，含未命中；`stage` 为 1 或 2，`damage` 为实际扣除生命 |
| `dango_showdown.frost_slash` | `side, target, point, radius, hit, damage, slow_seconds, slow_multiplier, energy, cooldown, hp_left, hp_right` | 每次环斩，含未命中；`point` 是施放者中心，伤害为实际扣血，附带减速参数、霜渐库存与下一次施放倒计时 |
| `dango_showdown.skill_damage` | `side, target, skill, damage, hp_left, hp_right, direction` | 单侧技能伤害 |

`point` / `normal` 使用核心 `Point` 或纯元组，不暴露 Qt 类型。
`hp_left` / `hp_right` 始终按场地左右排列，不随施放者改变；`skill_damage.skill` 为稳定技能 ID：
`starlight` / `starburst` / `void_hand` / `sun_spirit_yellow` / `sun_spirit_cyan` / `frost_slash`。

日灵的 `color` 仅为 `yellow` / `cyan`，`summon_id` 在一轮内唯一，用于关联出生与两次爆炸；
`sun_spirit_burst.point` 始终为固定出生点，不能用目标当前坐标替代。实际伤害继续走
`skill_damage`，与爆炸事件分开消费，避免伤害数字重复显示。
日灵充能的 `charge_changed.source` 为 `contact`（有效团子攻击）或 `wall`（撞墙概率充能）；
召唤消费能量时为 `sun_spirit`。满槽获得能量转为缩短冷却，不增加颜色；只有实际的能量格变化才发布充能变化事件。

霜渐使用 `charge_changed.meter_id=frost_energy`、`label=霜渐`、`slots=4`；
环斩未命中加能量时 `source=frost_slash`，有效身体攻击消耗时 `source=contact`。
环斩命中的实际伤害只通过一次 `skill_damage.skill=frost_slash` 消费；
`frost_slash` 事件报告刀光、命中、减速参数与库存，不能再次扣血或重复飘伤害数字。
减速参数只在命中且目标存活时施加，目标当前剩余时间以模型快照为准；未命中事件不能让目标进入减速。
`hit.damage_left` / `damage_right` 是各侧结算前后的生命差，包含霜渐附伤以及剩余生命不足时的截断。

### 8.2 共享粒子与图片效果

- 本包的 `manifest.extensions.particles` / `effects` 均为空，不携带私有粒子或特效运行时。
- 通过共享场景按已有原名取脚本：`floating_text`、`burst_line`、`star_streak`、
  `cyan_pink_scatter_fall`、`white_pink_collision`、`frost_snowflake`；图片效果使用 `smooth_image_show`。
- `frost_snowflake` 是本轮新增的宿主共享脚本，位于 `lib/script/practical/frost_snowflake_particle.py`，
  与桌宠其他粒子共用注册表、场景、生命周期及批次；不属于游戏包私有扩展。
- 包内只定义技能触发、素材、反馈参数和预警界面，不另建粒子实例更新器、图片动画播放器或音频合成器。
- 共享图片效果支持静图与 GIF；资源解码、动画取帧、缩放、旋转、透明度与绘制使用同一宿主实现。
  包格式仍支持其他游戏声明命名空间扩展，本包不使用该扩展入口。

### 8.3 技能接口（预留）

```python
class DangoSkillHook:
    def on_match_start(self, match) -> None: ...
    def on_hit(self, match, event) -> None: ...
    def on_low_hp(self, match, side) -> None: ...
    def on_match_end(self, match, result) -> None: ...
```

- v1 只提供空实现注册位；技能只能改事件表现，不修改基础生命扣减规则，
  除非显式扩展 `damage_rules` 并在文档中更新规则表。
- `on_low_hp(match, side)` 在普通撞击或技能伤害导致生命比例不高于 25% 时检查，每侧每轮只调用一次；新轮开赛重置。结束时调用 `on_match_end(match, result)`，扩展异常相互隔离。
- 内部 `DamageSink` 保留旧三参数及旧可选标记签名，支持时额外接收 `skill` 关键字；伤害回调内部异常不得通过重试再次扣血。

目视验收（`doc/AI协作规范.md` 第 5 节要求）：

1. `#团子大决战` 打开窗口，检查左右面板、正方形决斗区、顶栏是否对齐、无截断。
2. 选人 → 押注 → 开赛，确认比赛自动进行、撞墙反弹、每次撞击双方生命值同步下降。
3. 观察 idle / attack / hurt 三态拉伸差异、朝向翻转与受击闪红。
4. 分别看到「押中 / 押错 / 平局」三种结算：押中连续押胜 +1，押错清零，平局保持；
   关闭后重开存档仍在。

## 14. 风险与待确认

- **筹码的语义**：仍是纯计数筹码（1/5/10，当前值可为负），不接入任何货币或积分系统。
  若后续要接积分，需要另立规则并扩展存档字段。
- **比赛随机性**：初始两侧位置镜像，速度带随机仰角与独立大小；结果由物理过程产生。
  需要通过模拟检查左右胜率是否接近 50%，不能明显偏袒某侧。
- **平局**：双方同时归零时仍按平局结算；当前角色具备不对称技能与不同生命值，自然对战通常会产生胜者，不能把双方等量碰撞伤害理解为必然平局。
- **无超时判定**：v1 不设比赛时长上限；只靠纯物理碰撞与固定伤害结束本局。
- **窗口胶水**：若 render 层已有可复用的游戏画布宿主，可进一步消除 `widget.py` 的 PyQt
  导入；实现前先搜索 `lib/core/render/backends/qt/widgets/`，没有就不新增通用宿主。
- **拉海洛方块专属分支**：`lib/script/ui/game_runtime.py` 中存在
  `installed.game_id == "lahai_tetris"` 的开场语音硬编码，本包不受影响但也没有开场语音。
  后续可抽成 manifest 字段；不属于本包范围。
