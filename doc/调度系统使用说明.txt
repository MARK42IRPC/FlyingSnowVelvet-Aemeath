飞行雪绒调度系统使用说明（LTS1.0.6pre8）

一、核心实现
- 文件：`lib/core/timing/manager.py`
- 后端协议：`lib/core/timing/scheduler.py`
- Qt 实现：`lib/core/qt_bridge/scheduler.py`
- 对外入口：`lib/core/timing/__init__.py`
- 核心类：`TimingManager`
- 其他使用者：`ChatHandler` 的流式刷新/自动陪伴、`OllamaManager` 的周期探测

二、三套周期计时
调度核心维护三个独立的周期计时器句柄：
- `TICK`：固定 50ms
- `FRAME`：按 `frame_fps` 计算
- `GIF_FRAME`：按 `gif_fps` 计算

`TimingManager` 本身不依赖 Qt。桌面运行时由 `PetWindow` 注入 `QtScheduler`，无 Qt 的测试或未来自研运行时可注入同一 `Scheduler` 协议的其他实现。调度后端由单个 `TimingManager` 独占，退出时调用幂等 `cleanup()`，统一停止计时器、退订暂停事件并释放后端资源。

聊天与 Ollama 使用各自独占的 `Scheduler`，由 `ApplicationState` 在 Qt 桌面组合边界注入。聊天的 40ms 流式刷新和自动陪伴是 single-shot 业务语义：协议仍使用 `PeriodicTimer`，但回调入口先 `stop()`，完成后仅在需要时重新 `start()`。业务模块不得导入 Qt 调度实现作为缺省后备。

默认配置来自 `config/config.py` 中导出的 `ANIMATION`：
- `frame_fps = 120`
- `gif_fps = 16`

运行时可以通过 `TimingManager.set_frame_fps_limit(source, fps)` 注册来源独立的临时上限，
传入 `fps=None` 撤销对应来源。实际 FRAME 频率取用户配置帧率和全部临时上限中的最低值，
因此多个运行模式不会互相覆盖。工作台不会注册临时帧率上限，打开后继续使用当前有效 FRAME 频率。
`get_frame_fps()` 返回当前有效帧率；需要保存和恢复用户配置时使用 `get_configured_frame_fps()`。

三、周期事件
调度器会发布：
- `EventType.TICK`
- `EventType.FRAME`
- `EventType.GIF_FRAME`

对应常见字段：
- `tick_count`
- `frame_count`

四、定时任务机制
底层接口：
- `add_task(interval_ms, repeat=True)`
- `remove_task(task_id)`
- `pause_task(task_id)`
- `resume_task(task_id)`
- `clear_all()`

实体侧常用封装：
```python
task_id = pet.schedule_task(callback, delay_ms=1000, repeat=False)
pet.cancel_task(task_id)
```

执行流程
1. 业务调用 `schedule_task()`
2. `TimingManager.add_task()` 记录任务
3. 到时后发布 `EventType.TIMER`
4. 实体或管理器在对应回调中执行自己的 callback

五、时间精度
- 所有任务都按 50ms tick 对齐
- 小于 50ms 的任务会被提升到 1 tick
- 非 50ms 整数倍的延时会存在 tick 对齐误差

例子
- `1000ms -> 20 ticks`
- `120ms -> 2 ticks`
- `30ms -> 1 tick`

六、全局暂停
任务系统支持通过事件做引用计数式暂停：
- `TIMER_PAUSE`
- `TIMER_RESUME`

特点
- 只暂停任务系统，不暂停 `TICK / FRAME / GIF_FRAME`
- 不同模块可通过 `source` 区分暂停来源
- 常见场景：打开命令框或模态 UI 时暂停一部分行为任务

七、开发建议
- 高频业务优先订阅 `TICK` 或 `FRAME`，不要自己再开一套平行 QTimer
- 在 `cleanup()` 中移除任务并退订事件
- 构造 `TimingManager` 时必须在应用组合边界显式注入 `Scheduler`；业务模块不得直接创建 `QTimer`
- 静止对象不得在 `FRAME` 中重复移动窗口或触发重绘；临时降频应使用来源独立的帧率上限
- `PetWindow` 的 FRAME 层级入口只提交 `LayerManager` 中待处理的注册、注销或改层级变更；空闲帧不得周期性重申系统置顶。
- 物理对象空闲时应跳过屏幕查询和计算提交，重新获得速度或外部目标变化后再恢复计算。
- 对于需要高精度的逻辑，先评估 50ms tick 是否足够
- 服务类后台逻辑（如语音预热、网络轮询）如果不依赖 UI 节拍，可以使用线程或专用等待逻辑，不必强行接入 `TimingManager`
