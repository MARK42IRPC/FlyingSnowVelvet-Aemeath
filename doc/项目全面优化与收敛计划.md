# 项目全面优化与收敛计划（历史归档）

> 本计划对应 2026-07-24 的集中收敛工作，已完成主要实施与验证。当前维护入口为 [维护手册](维护手册.md)，后续任务应重新基于源码和测试确认范围。

## 目标

在保留当前未提交工作台改动、游戏包格式和用户数据的前提下，分阶段收敛项目边界、删除已证明无引用的历史代码，并修复退出、配置持久化、编码和发布流程中的高风险问题。

## 阶段

1. 建立测试与 CI 基线，修复计算线程、网络流、命令子进程和应用退出链路。
2. 将可变音乐设置迁移到稀疏用户配置，修复乱码，拆分核心、服务和开发依赖。
3. 删除无调用方的进程池、兼容访问器、插件/命令注册代码及旧对象渲染实现。
4. 继续完成工作台页面工厂、懒加载和 dataclass 数据流，保留当前工作树中的实现。
5. 收敛音乐后端、绘制、事件、游戏扩展和本地服务边界。
6. 合并普通版与绿色版发布逻辑，以服务源码生成发行 bundle，并执行完整回归。

## 兼容约束

- 保持游戏包 manifest、目录布局、加载语义和官方包隔离不变。
- 旧设置、登录状态、音乐历史和游戏统计保留一次性、幂等迁移；迁移后不再双读双写。
- 仓库内部调用方一次迁移完成，不保留无期限的未文档化内部 API 转发层。
- 不回退或覆盖实施前已存在的未提交改动。

## 验收

- 全量 `compileall` 和单元测试通过，CI 同时执行两者。
- 普通版及绿色版发布 dry-run 通过；缺失必需资源时给出精确诊断。
- 网络响应、子进程或后台任务运行时退出均可在有限时间内结束且无遗留进程。
- 用户数据迁移保持值不变并可重复执行；源码配置文件在运行期保持只读。
- 工作台未访问页面不在启动期构造；音乐、绘制、事件和游戏包契约测试通过。
