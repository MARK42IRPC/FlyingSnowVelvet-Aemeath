飞行雪绒事件系统使用说明（LTS1.0.6pre7）

一、核心入口
- 实现：`lib/core/event/center.py`
- 单例访问：`get_event_center()`
- 事件对象：`Event`
- 事件枚举：`EventType`

二、处理模型
- `publish(Event)` 将事件放入队列
- 主线程发布时，会尽快在主线程 drain 队列
- 非主线程发布时，会通过注入的 `EventPump` 切回事件中心所属线程处理；当前 Qt 后端使用 signal 实现
- 回调可以调用 `event.mark_handled()` 中断同类型事件后续传播
- 回调异常日志会记录事件类型、回调模块和限定名，并保留异常堆栈

三、基础用法
```python
from lib.core.event.center import Event, EventType, get_event_center

ec = get_event_center()

def on_info(event: Event):
    print(event.data)

ec.subscribe(EventType.INFORMATION, on_info)
ec.publish(Event(EventType.INFORMATION, {"text": "hello"}))
ec.unsubscribe(EventType.INFORMATION, on_info)
```

四、输入链路
- 鼠标：`MOUSE_PRESS` / `MOUSE_MOVE` / `MOUSE_ENTER` / `MOUSE_LEAVE` / `MOUSE_CLICK` / `MOUSE_DOUBLE_CLICK`
- `MOUSE_PRESS` / `MOUSE_CLICK` / `MOUSE_DOUBLE_CLICK` 的 `button` 使用 `input.types.MouseButton`，`global_pos` 与 `pos` 使用 `graphics.types.Point`
- `MOUSE_MOVE` 的 `buttons` 使用 `input.types.MouseButtons`，`global_pos` 与 `pos` 使用 `graphics.types.Point`
- Qt UI 消费核心坐标时，可直接读取 `Point.x/Point.y`，或在 QWidget 边界通过 `qt_bridge.window.coerce_qpoint()` 转换；不得对核心坐标调用 `x()/y()`
- 键盘：`KEY_PRESS` / `KEY_RELEASE`
- 命令框：
  - `/xxx` → `INPUT_COMMAND`
  - `#xxx` → `INPUT_HASH`
  - 普通文本 → `INPUT_CHAT`

五、应用生命周期
- `APP_PRE_START`
- `APP_INIT_READY`
- `APP_START`
- `APP_MAIN`
- `APP_EXIT`
- `APP_QUIT`

其中：
- `APP_PRE_START` 适合预热、静态准备和后台服务启动检查
- `APP_QUIT` 是统一退出请求入口，适合阻止直接粗暴退出；payload 可传 `restart: true`，由主生命周期在清理完成并释放单实例锁后重启
- 更新 helper 完成覆盖安装后才通过现有启动入口拉起新进程；普通重启调用“启动程序.bat”，环境重启调用“安装依赖.bat”，界面层不直接覆盖程序文件。

六、当前高频事件协议

INFORMATION
- 用途：信息气泡
- 常见字段：
  - `text`
  - `min`
  - `max`
  - `particle`

PARTICLE_REQUEST
- 用途：申请粒子
- 字段：
  - `particle_id`
  - `area_type`
  - `area_data`

EFFECT_REQUEST
- 用途：申请覆盖层特效
- 字段：`effect_id`、`anchor_type`、`anchor_data`、`effect_options`
- `anchor_data` 与 `effect_options` 只能包含 `None`、字符串、数值、布尔值、列表、元组和字符串键字典；发布工具会递归复制载荷并拒绝不透明后端对象
- 图片特效通过 `effect_options.resource_path` 传递资源路径，文字特效传递文本、颜色数组和字体参数；不得传入 `QPixmap/QImage/QColor/QFont/QPainter` 等 toolkit 对象
- 当前由 `lib/core/qt_bridge/effect_system.py` 消费；资源加载、文字栅格化和后端图片缓存只发生在适配层

SOUND_REQUEST
- 用途：请求播放音频文件
- 字段：
  - `audio_class`
  - `file_path`
  - `volume`
  - `interruptible`

VOICE_REQUEST
- 用途：语音播放抽象层入口
- 当前文本类请求会继续分流到 `AI_VOICE_REQUEST`

AI_VOICE_REQUEST
- 用途：AI 文本转语音申请
- 字段：`text`（保留中英文原文）、可选 `text_lang`（`zh`、`en` 或 `auto`）、`interruptible`
- 当前由 `lib/script/gsvmove/service.py` 消费
- 当 GSV 模块在控制面板中关闭时，这类事件会被直接忽略

STREAM_FINAL
- 用途：发布 AI 最终回复，供记忆和工具调度消费
- 字段：`text`、可选 `allow_tool_commands`、可选 `tool_call`
- `tool_call` 为通过 `lib/script/chat/native_tools.py` 白名单校验的原生 Function Calling 调用；存在时工具调度器优先使用它，不再解析正文里的兼容标记
- `allow_tool_commands=false` 时，结构化调用和 `###指令###` 均不得执行

CONFIG_UPDATED
- 用途：通知运行时配置已完成热更新
- AI 设置保存时 payload 的 `source` 为 `ai`；聊天处理器会据此立即重排自动陪伴定时器

MIC_STT_*
- `MIC_STT_START`
- `MIC_STT_STOP`
- `MIC_STT_PARTIAL`（保留兼容事件；当前整句识别路径不发布实时增量文本）
- `MIC_STT_FINAL`（完成端点检测、整句降噪和 Vosk 识别后发布）
- `MIC_STT_STATE_CHANGE`

MUSIC_*
- 播放控制、登录状态、进度同步、队列操作都在 `MUSIC_*` 命名空间
- 统一由音乐服务和 UI 组件解耦协作

MANAGER_SPAWN_REQUEST
- 用途：请求对象管理器生成实体
- 常见字段：
  - `manager_id`
  - `count`
  - `spawn_type`

MANAGER_QUERY_REQUEST / MANAGER_QUERY_RESPONSE
- 用途：跨管理器查询状态、数量、保护范围等

TARGET_POSITION_QUERY / TARGET_POSITION_RESPONSE
- 用途：统一查询目标位置，减少状态机与具体管理器的直接耦合

PROTECTION_CHECK / PROTECTION_RESPONSE
- 用途：检测主宠保护半径或实体保护区

UI_ANCHOR_RESPONSE
- 用途：发布窗口或 UI 锚点的全局桌面坐标
- 字段：`window_id`、`anchor_id`、`ui_id`、`anchor_point`
- `anchor_point` 固定使用 `lib.core.graphics.types.Point`；Qt 控件只在事件消费边界转换为 `QPoint`

ENTITY_POSITION_RESPONSE / ENTITY_STATE_RESPONSE
- `ENTITY_POSITION_RESPONSE.position` 固定使用 `Point`，`size` 为 `(width, height)` 数值元组
- `ENTITY_STATE_RESPONSE.position` 与 `target` 存在时同样使用 `Point`
- 事件 payload 禁止放入 `QPoint/QRect/QWidget` 等 toolkit 对象

七、开发约束
- 回调应尽量短小，避免阻塞 UI
- 配置保存、更新下载、语音安装和麦克风初始化等 I/O 必须交给 `ComputeHub.submit_interactive_io()` 或所属后台 Worker；事件回调只负责提交任务和更新状态。
- 所有订阅都必须在 `cleanup()` 中退订
- `mark_handled()` 只用于确实需要阻断传播的场景
- 公共事件字段一旦公开使用，尽量保持兼容，不要频繁改 key
- 几何字段统一使用 `lib.core.graphics` 值类型，不得从 Qt UI 反向泄漏原生对象
