# 跨后端视觉表现契约

更新时间：2026-08-17

本文档定义桌面后端与视觉表现之间的稳定边界。目标是让同一业务状态只生成一份后端无关的视觉描述，Qt、DirectX 及后续后端只负责等价执行绘制、窗口和资源命令，不再各自决定产品的颜色、布局、字体、动效或特效算法。

当前 Qt 后端的实际表现是视觉迁移基准。这里的“以 Qt 为基准”指保留用户当前看到的尺寸、排版、颜色、透明度、层级、动画和特效语义，不是把 `QWidget`、`QPainter`、`QFont` 或 Qt 的隐式默认值继续作为跨后端契约。

## 1. 事实源与适用范围

视觉表现按以下顺序确定：

1. 本文档定义所有后端必须遵守的职责边界。
2. 尚未抽离的场景以当前 Qt 后端在受控字体、资源、DPI 和状态下的输出作为基准。
3. 抽离完成后，以共享主题快照、视觉描述、声明式命令和跨后端基线测试为事实源。
4. 有意调整样式时只修改共享视觉层并更新基线，不在某个 bridge 中单独修正。

契约覆盖主宠、粒子、特效、世界对象、提示、命令输入、二维码、公告、工作台、设置页和游戏画面。工作台、复杂对话框及部分游戏目前仍是 Qt 独占实现，但后续迁移也必须遵守同一边界。

托盘菜单外壳、输入法候选窗和系统文件对话框等由操作系统绘制的原生界面可以保留平台外观；产品提供的图标、文案、状态和命令结构仍由共享层决定。

## 2. 依赖方向

```text
业务状态、用户配置、资源
  -> 后端无关视觉层
       - 主题与设计 token
       - 组件状态映射
       - 布局和文字排版
       - 动画、粒子与特效参数
       - 资源选择、采样与合成语义
  -> 不可变视觉描述 / DrawBatch / 窗口描述
  -> Qt、DirectX 或后续后端
       - 资源上传与缓存
       - 命令栅格化和合成
       - 窗口、目标、设备与呈现
```

视觉层只能依赖纯数据类型、配置和业务状态，不得导入 `PyQt5`、`qt_bridge`、`dx_bridge`、Win32 或 DirectX 类型。后端不得反向读取业务对象、页面状态或配置文件来补全视觉信息。

视觉层不要求所有场景共享一个巨型模块。通用 token、文字与绘制语义属于核心纯数据契约；具体页面、对象或效果的 presenter/composer 可以留在对应业务模块，但必须生成相同的后端无关视觉描述。

## 3. 视觉逻辑的定义

以下内容全部属于视觉逻辑，必须位于后端之外：

- 颜色、字体族、字号、字重、行高、间距、边距、圆角、描边宽度、阴影和透明度；
- 控件、页面、提示、对象和粒子在不同业务状态下采用的样式；
- 布局约束、换行、截断、对齐、文字基线和空状态占位；
- 资源选择、帧选择、目标尺寸、翻转、旋转中心、采样模式和像素对齐策略；
- 动画时序、缓动、插值、bloom、羽化、发光、拖尾及 alpha 分配算法；
- 绘制命令的数量、顺序、变换、裁剪和 `layer/z/order`；
- 亮色/暗色主题及 hover、pressed、disabled、focused 等状态映射。

后端可以提供低级文字度量和字形栅格化能力，但不得自行决定字体回退、字号、换行、截断或对齐。迁移完成后的文字命令应携带已经确定的排版结果或足以产生唯一排版结果的完整约束；在此之前，Qt 与 DirectWrite 的度量差异属于待消除的兼容债务，不能用后端私有偏移量长期掩盖。

抗锯齿和字形 hinting 可以因栅格器不同产生有限的边缘像素差异，但抗锯齿模式、采样质量和合成语义必须由命令契约明确。后端不能用“原生默认值”替代未声明的视觉决策。

## 4. 共享视觉数据

目标视觉层至少提供以下纯数据：

- 主题快照：一次渲染使用的颜色、排版、间距、描边、阴影和效果 token；
- 组件视觉状态：业务状态到共享样式和资源的解析结果；
- 布局结果：逻辑坐标中的确定矩形、基线、裁剪区和变换中心；
- 绘制批次：只包含已解析资源和完整绘制参数的不可变 `DrawBatch`；
- 窗口视觉描述：内容尺寸、透明背景、输入区域和需要的原生窗口能力。

`SpriteCommand.target_size` 是共享视觉层解析后的逻辑目标尺寸；为空时才使用源帧尺寸与 `scale`。`DrawBackend.render(..., viewport=...)` 的 `viewport` 只表示目标上的重绘/裁剪区域，不得替代 sprite 目标尺寸或改变资源缩放。

主题快照在一帧或一次页面构建期间不可变。后端只接收快照解析后的命令，不读取 `config/config_ui.py`、`workbench/theme.py` 或其它配置来选择颜色和字号。

现有命令不能唯一表达 Qt 基准时，应先扩展纯数据契约，再实现 Qt 与 DX 两个执行器。典型缺口包括 sprite 采样模式、线帽与连接方式、文字基线和排版结果、渐变、阴影、混合模式及边缘羽化；禁止在两个 bridge 中用不同私有算法分别近似。

## 5. 坐标、DPI 与颜色

- 桌面窗口位置、显示器边界和 Win32 交互几何使用物理桌面像素，可包含负坐标。
- 窗口内容布局、字号、形状和 `DrawBatch` 使用 96 DPI 逻辑像素。后端在目标边界按 `dpi / 96` 换算一次，不得在资源、命令和窗口提交的多个阶段重复缩放。
- 主宠等固定内容窗口必须由共享批次显式携带目标尺寸；源图片尺寸、Qt paint viewport 和 DX swap-chain 尺寸都不是产品尺寸的事实源。
- 布局保留浮点精度。需要落在设备像素中心的细线或像素画，由共享视觉层明确像素对齐和采样模式，后端不得自行四舍五入布局。
- `Color` 和源图片按 sRGB RGBA 解释；命令透明度与源 alpha 使用统一的 source-over 语义。后端可为 GPU 上传转换为预乘 alpha，但不能改变视觉层声明的最终合成结果。
- 旋转方向、变换矩阵顺序、裁剪包含规则和边界取整必须由命令契约统一，不依赖 QPainter 或 Direct2D 的默认行为。

## 6. 后端职责

绘制后端只负责：

- 创建和销毁窗口、绘制目标、交换链及设备资源；
- 将纯 RGBA 资源和字体资源转换为原生对象并按 revision 管理缓存；
- 按批次顺序执行 sprite、文字、形状、裁剪和变换命令；
- 根据显式 DPI、采样、抗锯齿、混合和颜色空间参数完成栅格化；
- 呈现、readback、设备恢复、错误诊断和幂等清理。

后端禁止：

- 保存产品主题色、字号、边距、圆角、阴影或 bloom 等视觉常量；
- 根据“主宠”“粒子”“提示”“设置页”等业务类型选择画法；
- 读取用户主题配置或根据当前后端修改布局和效果参数；
- 把一个业务效果临时展开为私有绘制算法，同时让另一个后端走不同算法；
- 为通过对比测试添加只对 Qt 或 DX 生效的视觉补丁。

透明清屏色、像素格式、缓冲数量、缓存容量和设备恢复阈值属于渲染技术参数，可以留在后端；它们不得改变同一视觉描述的产品语义。

## 7. Qt 基准抽离顺序

1. 固定代表性 Qt 场景、资源、字体、DPI、时间点和交互状态，保存参考截图及几何数据。
2. 盘点 `config/config_ui.py`、`lib/script/workbench/theme.py`、Qt 控件样式和 painter 路径中的视觉常量，整理为纯数据主题快照。
3. 将 Qt 中的布局、文字排版、粒子、特效和状态样式迁到后端无关 presenter/composer，由其生成不可变视觉描述。
4. 让 Qt 后端改为消费同一视觉描述，确认输出仍符合迁移前基准。
5. 删除 `dx_bridge` 中重复的产品色值、布局和效果生成逻辑，让 DX 只执行共享命令。
6. 补齐命令契约中无法表达的采样、混合、文字和效果字段，再进行跨后端像素对比。
7. 按主宠、粒子/特效、世界对象、应用级 UI、工作台/设置、游戏的顺序扩大覆盖面。

粒子、特效运行时、命令输入框外壳、命令框相对主宠的锚点/屏幕夹取和七类世界对象批次已由 `lib/core/graphics/visuals.py` 统一生成命令批次或纯几何结果，Qt 与 DX 消费同一结果。世界对象共享描述覆盖 sprite 目标尺寸、透明度、翻转、动画帧、中心缩放、摩托抖动、音响 EMA/指数缩放以及闹钟倒计时文字；音响缩放先应用 `SPEAKER_AUDIO.response_gain`，再由 `scale_range` 限制最大形变，确保常用播放音量下仍有可辨识响应。Qt 世界对象只向 `QtDrawBackend` 提交批次，DX world object bridge 只提交同一批次。二维码主体、action button 的文案与完整交互状态、DX 基础通知和 Qt 聊天气泡由 `lib/core/graphics/application_visuals.py` 生成：Qt `BaseQrDialog` 与 DX application UI 共用二维码主题、`320x430` Qt 基准尺寸、布局、资源解码、sprite 目标尺寸和 `action_rect`；Qt 的透明 `QPushButton` 与 DX pointer handler 只把输入状态转交共享 presenter。`BubbleVisualDescription` 统一气泡换行、自适应尺寸、三层背景、混合字体分段、锚点和屏幕夹取，Qt 只通过 `BubbleTextMetrics` 注入低级字体度量并执行同一批次。bridge 只选择 presenter、管理窗口/输入/生命周期并执行批次。

命令提示框的三层背景、自适应尺寸、默认/哈希行、选中态、分隔线、混合字体、页码、默认文案和命中矩形已由 `CommandHintVisualDescription` 统一，Qt 只提供低级字形度量、使用共享命中矩形并执行批次；DX 原生提示宿主执行同一描述并承接筛选、导航、补全、翻页和点击。真实 DX host 使用 ABI v9 DirectWrite metrics，无测量能力的测试宿主使用 portable 回退；两者都只能替换低级度量，不能改变 presenter 逻辑。鼠标穿透、放大、缩小、关闭、启动鸣潮、聊天模式、交互模式和更多功能八个矩形附属按钮的 normal/hover/pressed 背景层、内容区、字体、居中文字和三行布局已由 `build_rect_action_button_visual()`、`build_command_action_panel_visual()` 统一；“更多功能”固定在“启动鸣潮”正上方，交互模式文案只允许为“陪伴模式”或“办公模式”，由共享状态决定，DX 单窗口宿主只执行批次和命中矩形。`BubbleVisualDescription` 已同时由 Qt `Bubble` 和 DX `_DxBubbleWindow` 消费，`INFORMATION` 的消息队列、尺寸、锚点和批次不再由两个后端分别决定；DX 同样在真实宿主使用 DirectWrite 低级度量。固定系统通知与聊天气泡是不同组件，不能复制 notice presenter 或 Qt 画法。

办公任务页复用设置面板语言：页头（`SettingsPageHeader`）与双栏卡片（`SettingsSection`）由 `lib/script/ui/office_page.py` 组合，颜色、字体、粉青强调条、输入控件、页签、状态标签和主次操作统一由 `lib/script/ui/office_style.py` 自包含生成。办公页不再使用粉青渐变条（保留给权限许可窗），复用 `lib/script/ui/workbench_settings_layout.py` 的页头/卡片组件但仍共享 `get_workbench_colors` 令牌、不复制颜色常量。页面可以消费工作台明暗主题，许可窗不能另建独立配色；后续迁移到其它 toolkit 时以该共享样式的状态映射和离屏截图为 Qt 基准。

视觉或交互查询不得以 getter 名义隐式构造 toolkit UI。跨后端控制逻辑需要窗口几何时，由活动宿主向核心注册 `Point/Rect` provider；例如游戏区域避让统一读取 `lib/core/game_obstacles.py`，主宠状态机不导入 Qt 游戏 runtime。DX 没有对应宿主时 provider 返回空，而不是创建 `QWidget` 作为兼容路径。

## 8. 验证标准

自动化至少覆盖：

- 同一业务状态和主题快照在选择 Qt、DX 或 Fake 后端时生成完全相同的视觉描述和 `DrawBatch`；
- Qt 参考截图与共享视觉层迁移后的 Qt 输出对比，防止抽离过程改变既有样式；
- 同一批次分别经 Qt 和 DX/WARP 渲染后的像素对比，覆盖 sprite、透明度、形状、文字、裁剪、变换、粒子和特效；
- 100%、125% 和 150% DPI 下的窗口内容尺寸、基线、裁剪区和变换中心；
- 亮色/暗色及 normal、hover、pressed、disabled、focused 状态；
- 静态扫描 bridge 中新增的产品视觉常量和业务类型分支。

当前 `tests.test_visual_presenters` 以 AST 审计整个 `lib/core/dx_bridge/`：DX bridge 不得导入 PyQt，也不得实例化 `Color`、`FontSpec`、`RectCommand`、`TextCommand`、`SpriteCommand` 或其它产品绘制命令；同一测试还禁止 Qt 粒子、特效和七类世界对象宿主恢复私有产品绘制调用。应用面板结构、Qt 消费路径和 Qt/DX-WARP 二维码像素对比可由以下命令执行：

```powershell
$env:FLYING_SNOW_DX_DLL = (Resolve-Path 'native/dx_backend/build/cmake/Release/flying_snow_dx.dll')
py -3 -m unittest tests.test_visual_presenters tests.test_bubble_visual tests.test_qr_panel_visual tests.test_visual_backend_parity
```

几何、布局、颜色、alpha、资源选择和动画取样必须一致。文字边缘允许按用例设置很小的栅格化容差，但文字边界、基线、换行和占位不得因后端不同而变化。像素容差必须随测试用例版本化，不能用一个宽松的全局阈值掩盖布局偏差。

手工验收以 Qt 与 DX 同机、同 DPI、同字体、同资源和同业务状态的并排截图为准，覆盖主宠闲置/拖拽、聊天、提示、粒子、特效、世界对象及所有已迁移页面。

## 9. 完成条件

视觉抽离完成需要同时满足：

- 同一状态只生成一份后端无关视觉描述，不存在 Qt/DX 两套主题、布局或效果算法；
- `qt_bridge`、`dx_bridge` 只保留渲染技术常量，不含产品视觉常量和业务画法；
- Qt 输出保持当前基准，DX 在规定容差内通过跨后端对比；
- DPI、字体、采样、混合和变换语义已成为显式契约；
- 后续样式调整只需修改共享视觉层一次，所有后端同步生效。

DirectX 的实验性标记不能仅凭功能可启动移除；代表性视觉场景达到本契约的 Qt 基准并通过真实硬件、多屏和混合 DPI 验收，也是稳定后端闸门的一部分。
